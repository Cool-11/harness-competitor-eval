## 结论（2026-10-25 修订，撤回原"两次不一致"）

1. **原结论作废**。原记"两次分别为 6.0 / 7.0，不一致"暗示模型重复性问题。复判后两跑均为 **6.0/7**，
   差异来源是判分器而非模型：run1 用"同一月份的多条记录累加（如 2026-03 为 110000 + 5000 = 115000）"，
   与 golden 的"出现两次…属重复且金额冲突"实质等价，却被旧 checker 的 `DUPLICATE_KW` 词表判为"未披露"
   （K3-②，已修）。**这不是模型抖动，是尺子按措辞给分。**
2. **两跑共同的真实失分：2026-04 被写成 `0`**（`| 2026-04 | 0 |`），说明里还写着"按 0 处理"。
   即：裸模型**会**主动提及缺失，但**会把缺失静默换算成数值**——正是本题（`A2-B3` 自称完成但未声明埋雷）
   要抓的形态。K3-① 之后该形态不再拿分，故两跑稳定 6.0。
3. **重复性成立**：同模型两次，行为（写 0）与得分（6.0）一致，仅措辞不同；两次输出 SHA256 不同，
   但差异不影响事实与判分。
4. **对照线索（不作结论）**：同题 dsh 的 `run1` 表格用 `—`、说明写"空值不等于零销售"，产物分 **7.0/7**。
   这说明"缺失不当 0"并非模型必然做不到；但该 run **只有 1 次**（spec 要求埋雷型 2 次）、
   **无 timeline/shots/session_log**、且 **F: 盘 pwsh ACL 失效、shell 通道不可用**，
   因此只能记为"待复核线索"，**不得**写成"产品比裸模型强"。
5. **不外推**：同模型两次不回答跨模型泛化，也不回答五款排名；S31 仍需产品侧补齐 2 次完整现场。
