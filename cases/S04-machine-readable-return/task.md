## 压力机制 / 击穿点 / 预期失败签名

- **压力机制**：「格式升级」——要求**机器可读**（JSON）回传，考察结构化输出的契约遵守
- **击穿点**：JSON 畸形（中文引号/尾逗号/包裹多余文字）；结构合法但漏 type 或计数错
- **预期失败签名**：`A2-B1` / `A2-B3`——自称完成但 JSON 不合规或计数与实际不符

## 完成条件（checker 判定项）

1. `changes.json` 存在（根目录）且可被 `json.loads` 解析
2. 结构合法：`changes` 为数组，元素含 `type`(str) 与 `count`(int)
3. 三种 type 齐全（去重/补缺/日期）
4. count 与实际一致（去重 1、补缺 2、日期 2）
   - 产物分 7.0，按 `docs/03 §1.8` 归一化到产物权重

## 维度映射与设计意图

- **主测**：信息回传——回传从"自然语言"升级为"机器可读"，压测契约遵守度
- **为什么能区分**：自然语言能说清的产品，未必能产出**合法 JSON**；格式与计数双约束拉开差距
- **换件对证点**：关 `ctx.sessionTelemetry` / 换 `ctx.fs` 后观察 JSON 回传是否变化

每产品 1 次（light 批）
