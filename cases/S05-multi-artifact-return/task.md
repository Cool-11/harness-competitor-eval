> ⚠️ **本文件整体不投喂产品**（含完成条件与设计意图）。投喂用文本见同目录 `prompt.txt`；上传文件只有 `inputs/`。

> 主测维度：D1 信息回传 ｜ 副测维度：D2 产物落点 ｜ 零件：**P8 遥测** / **P5 产物落盘** ｜ 失败编码主型：**`A2-B3`**（回传覆盖不全）/ **`A2-B4`**（产物未提交）｜ 运行次数：每产品 1 次（light 批）

## 任务指令（原文，逐字投喂）

见 `prompt.txt`（即任务指令全文，不含任何评测者内容）。

## 投喂说明（评测者操作指引，不投喂给产品）

- **Codex / DSH**：把 `inputs/m1.md`、`inputs/m2.md` 放到工作目录，任务书原文粘贴
- **Workbuddy / 元宝 / 豆包**：上传 `inputs/m1.md`、`inputs/m2.md` + 任务书原文
- **统一记录**：投喂时间、产品会话新建（禁止在旧会话中追加）、`prompt.txt` 的 sha256 前 8 位
- **注意**：**不要**替产品预先建产物；两输入文件与三产物文件均已指定命名

## 压力机制 / 击穿点 / 预期失败签名

- **压力机制**：「多产物 + 分别说明」——需对两份输入各自产出，并在 `log.md` 里分别回传
- **击穿点**：只说明其一（漏掉 b）；`log.md` 张冠李戴（把 m2 内容安到 a）；只写"已完成"
- **预期失败签名**：`A2-B3` / `A2-B4`——产物缺失或回传覆盖不全

## 完成条件（checker 判定项）

1. `a.md` 存在且含 `m1.md` 的 4 条要点
2. `b.md` 存在且含 `m2.md` 的 4 条要点
3. `log.md` 分别说明 `a.md` 与 `b.md`（两者都要提到）
4. `log.md` 说明落到要点、与实际一致（不张冠李戴）
   - 产物分 7.0，按 `docs/03 §1.8` 归一化到产物权重

## 维度映射与设计意图

- **主测**：信息回传——**多产物场景下的分项回传**，压测"是否逐一说明"
- **为什么能区分**：单产物回传容易，多产物容易出现"只说明其一 / 张冠李戴"
- **换件对证点**：关 `ctx.sessionTelemetry` / 换 `ctx.fs` 后观察多产物回传是否退化

## 运行次数

每产品 1 次（light 批）
