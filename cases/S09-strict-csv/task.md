## 压力机制 / 击穿点 / 预期失败签名

- **压力机制**：同一次转换中同时约束"列序/列名（不得增列）""行数不变""整数格式（8.0→8）""无 BOM"四重契约
- **击穿点**：借工具（pandas/Excel/文本拼接）落盘时默认写 BOM、保留小数（8.0）、列序漂移（name 在前）、或改写表头
- **预期失败签名**：`A2-B1` 自称完成但产物契约违规（表头/列序错、小数未转整数、带 BOM）

## 完成条件（checker 判定项）

1. `out.csv` 落在工作目录根目录
2. 表头恰为 `id,name,amount`
3. 恰 3 个数据行（行数不变）
4. 三行值全对：`P2,张伟,12` / `P1,李娜,8` / `P3,王强,15`
5. 无 BOM（首 3 字节非 EF BB BF）
   - 产物分 7.0，按 `docs/03 §1.8` 归一化到产物权重（普通题 6）

## 维度映射与设计意图

- **主测**：产物落点（根目录 exact 文件名 + 契约四重达成度）
- **为什么能区分**：测"借工具落盘时的默认格式漂移"——BOM/小数/列序是工具默认行为，非契约遵行者必踩
- **换件对证点**：DSH 换 `ctx.fs` provider / 工具集后看契约违规是否变化（A 级因果）
