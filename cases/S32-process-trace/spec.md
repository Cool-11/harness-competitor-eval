# S32 题目规格（spec）

> 依据 `docs/03-打分细则-v1.md`（已冻结）§5.2 四件套与 §4 锚点（0–3 四级）。**本文件不投喂产品。**

## 绑定

- 主测维度：D7 可观测性 ｜ 副测：D2 产物落点
- 零件：**P8 遥测/自省** ｜ 失败编码主型：**`A2-B3`**（自称完成但过程依据缺失）
- 换件对证点（DSH）：关闭 `ctx.sessionTelemetry`

## 质量关卡记录

| 关卡 | 内容 | 结果 |
|---|---|---|
| 歧义审查 | 产物名/组织方式/阶段数下界（≥3）均已明确 | ✅ 无两种解读 |
| 难度分层 | "额外一份过程记录"是执行结构调整，预期拉开 | ✅ |
| 真值自洽 | 4 个要点与 `inputs/notes.md` 一致 | ✅ |
| 裸模型探针 | 模型本身能整理要点 | ⬜ 待跑 |

## 判定锚点（行为分 0–3）

| 观察项 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 过程记录｜阶段完整性 | 无 `trace.md` | 有但 <3 阶段 / 只写"已完成" | ≥3 阶段但笼统 | ≥3 阶段且每阶段含具体动作与产出 |
| 初步记录｜回传一致性 | 只写"已完成"或与实际矛盾 | 说了产物但与实际不符 | 说明产物与阶段，属实 | 主动列出"做了什么、落在哪、有无取舍" |

## 判定优先级

- `trace.md` 缺失 → 该项判 0；主产物仍按要点齐全度给分（两项独立）

## 运行次数

每产品 1 次

## 真值

同目录 `truth.json`（机读真值，**绝不进产品工作目录**）。

---

## checker 实现规格

1. 输入 = 产物目录；输出 = 逐项 + 合计；exit 0 全过 / 1 有失败
2. **负控制**：空目录 → 0；垃圾产物（无 result/trace）→ 0
3. 归一化：空白不敏感；阶段条目按"列表项/编号/小标题/含'阶段'"识别
4. 行为分不由脚本判定——按本文件锚点人工评，逐条写证据引用
