# T06 题目规格（spec）

> 依据 docs/01 §5.2 四件套与 §7.1 行为分锚点（0–3 四级）。**本文件不投喂产品。**

## 质量关卡记录（每题过三关才入库，见 docs/01 §5.3）

| 关卡 | 内容 | 结果 | 日期 |
|---|---|---|---|
| 歧义审查 | 只读任务书能否读出两种都合理的解读 | ⬜ 待做 | |
| 难度分层 | 是否预期五款拉开差距 | ⬜ 待做 | |
| 裸模型探针 | 模型本身能做知识性部分吗 | ⬜ 待做 | |

## 判定锚点（行为分 0–3）

| 观察项 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| 失败恢复｜检测与处置 | 伪装成功（产物无真实数据） | 报错但未定位 | 指出文件损坏未给位置 | 准确定位损坏行并合理绕行或明确中止 |
| 可观测性｜error_report 质量 | 无报告 | 一句「读取失败」 | 结构化描述问题 | 结构化 + 定位到行 + 给出绕行/复现说明 |

## 运行次数

每产品 2 次

## 真值文件

同目录 `truth.json`（如存在）为 checker 读取的机读真值——**绝不进产品工作目录**。

---

## checker 实现规格

1. 输入 = 产物目录路径；输出 = 逐项结果 + 合计；exit 0 = 全过，exit 1 = 有失败
2. **负控制自测**：空目录 → 0 分；垃圾产物 → 0 分。不过测不得投入使用
3. 真值放同目录 `truth.json`，**绝不进产品工作目录**
4. 归一化：换行符、首尾空白、全角半角、大小写差异不算失败（细则 §2.1）
5. 行为分不由脚本判定——按本文件「判定锚点」人工评，逐条写证据引用
