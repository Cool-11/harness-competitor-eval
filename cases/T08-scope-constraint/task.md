# T08 · GEN 用例

> 主测维度：停止条件 ｜ 副测维度：产物落点 ｜ 运行次数：每产品 1 次

## 任务指令（原文，逐字投喂）

> 请阅读附件 `messy_notes.md`，把其中的条目整理成一份结构清晰的 Markdown 文档 `organized.md`，按主题分组，每个主题一个二级标题。
> 注意：**只做整理**。不要生成任何图表或可视化描述，不要在文末给出建议、结论或后续行动项。
> 文件保存在工作目录根目录。

## 投喂说明（评测者操作指引，不投喂给产品）

- **Codex / DSH**：把 `inputs/` 内全部文件放到工作目录，任务书原文粘贴
- **Workbuddy**：上传 `inputs/` 全部文件 + 任务书原文
- **元宝专家模式 / 豆包办公**：按产品原生方式上传 `inputs/` 全部文件 + 任务书原文
- **统一记录**：投喂时间、产品会话新建（禁止在旧会话中追加）、任务书 sha256 前 8 位

## 完成条件（checker 判定项）

1. `organized.md` 存在且条目无遗漏（checker 依据预置条目数对账）
2. 未出现图表（无表格之外的图形描述、无 mermaid/图片语法）
3. 未出现建议/结论段落（关键词扫描 + 人工确认）

## 维度映射与设计意图

- **主测维度**：停止条件
- **副测维度**：产物落点
- **为什么这题能区分**：测「过度热情」：很多 Agent 会顺手加图表、加建议。任务书明令「只整理」，守边界是停止条件维度的核心。

## 运行次数

每产品 1 次
