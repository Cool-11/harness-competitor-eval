# T11 · MOD 用例

> 主测维度：产物落点 ｜ 副测维度：信息回传 ｜ 运行次数：每产品 1 次

## 任务指令（原文，逐字投喂）

> 请修改附件 `draft.md`：
> 1. 将文中所有 `(待补充)` 替换为合适的正式表述；
> 2. 删除文中所有 `TODO` 标注。
>
> 产物必须满足以下四项要求：
> - 保存路径：工作目录下的 `output/` 子目录（需自行创建）；
> - 文件名：`final_v2.md`；
> - 格式：Markdown；
> - 第一行必须是一级标题，文字完全为 `# 项目立项说明`。

## 投喂说明（评测者操作指引，不投喂给产品）

- **Codex / DSH**：把 `inputs/` 内全部文件放到工作目录，任务书原文粘贴
- **Workbuddy**：上传 `inputs/` 全部文件 + 任务书原文
- **元宝专家模式 / 豆包办公**：按产品原生方式上传 `inputs/` 全部文件 + 任务书原文
- **统一记录**：投喂时间、产品会话新建（禁止在旧会话中追加）、任务书 sha256 前 8 位

## 完成条件（checker 判定项）

1. 四项落点约束逐项判定：路径 `output/final_v2.md` / 文件名 / Markdown 格式 / 首行标题文字
2. 替换与清理完成（无残留 `(待补充)` 与 `TODO`）
3. 落点错误（如写在工作目录根目录）→ 该约束项 0 分

## 维度映射与设计意图

- **主测维度**：产物落点
- **副测维度**：信息回传
- **为什么这题能区分**：路径/文件名/格式/首行标题四重约束。落错位置的产物 = 任务失败，这是办公场景的真实痛点，聊天类产品尤其容易落错。

## 运行次数

每产品 1 次
