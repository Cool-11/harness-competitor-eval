# 04 · 开源 Harness 基准借鉴登记

> 触发：评测者质疑现有题目"过于简单"（2026-10-15）
> 结论先行：**公开基准的"题"不能直接搬（产品形态/模型不固定），但它们的"机制"必须搬——其中三条机制正好补我们的短板。**
> 本文登记：各基准定位 → 可搬/不可搬 → 对 14 题库的具体改造建议。

## 1. 相关工作盘点（均可开源获取）

| 基准 | 出处 | 定位 | 对本项目的价值 |
|---|---|---|---|
| **Terminal-Bench 2.0** | github.com/laude-institute/terminal-bench | 89 道终端任务，pytest 确定性判分，harness 无关设计；官方提供中性脚手架 Terminus 2 作模型基线 | 同模型换脚手架可差 17 分——直接支撑"评 Harness 不评模型"的立项依据；其难度分层（easy ~65% / hard ~16%）是区分度设计参照 |
| **OpenBench** | github.com/minghinmatthewlam/openbench (MIT) | **专门比较 coding-agent harness 的开源框架**：固定同一模型，测 run loop/工具集/权限策略的差异；外部 checker 判分（exit 0 + SCORE 部分分），结果带 Wilson 95% CI | 与本项目方法同构（同任务同判分、归因给脚手架），其三条机制直接可搬，见 §3 |
| **WildClawBench** | github.com/internlm/WildClawBench (InternLM) | 60 道原创任务，四款 harness（OpenClaw/Claude Code/Codex CLI/Hermes）跑同一套题同判分；Docker 隔离；**真值与判分脚本只在 agent 结束后注入** | "四 harness 一套题"= 我们"五产品一套题"的学术版；防泄漏机制必须搬 |
| **Harness Arena** | AIREV（开源平台） | 同一任务给多框架，**盲评**（评委不知产出方）+ rubric 打分 + Elo 排名 | 盲评机制可搬进"同学抽样复评"，与 kappa 计划天然衔接 |
| **GAIA** | Meta/HF（466 题） | 文件型多步助理任务，最接近我们办公场景；HAL 榜单显示同模型换脚手架分差 43.6 分 | 立项论据 + 任务设计模式（文件投喂→多步→精确答案）参照 |
| **The Scaffold Effect** | KDD 2026（Vats & Golev，已在精读清单） | 同模型固定，三 harness × 50 题 × 300 试验：通过率几乎持平，**token 成本差 40 倍；失败方式按 harness 分型复现**（Goose=想不通干净停手 / OpenHands=验到回合上限 / OpenCode=空转超时） | **我们的"失败指纹跨复现判定法"已有实证文献背书**——报告相关工作章节必引 |

## 2. 为什么不能直接搬题

1. **产品形态不兼容**：Terminal-Bench/SWE-bench 任务要求终端与代码仓库——Codex/DSH 能做，Workbuddy/元宝/豆包根本没有文件系统执行环境，题干都不成立
2. **模型无法固定**：OpenBench 区分度的前提是"pin 同一模型"，我们四款闭源产品换不了模型——难度加在知识层面只会放大模型差异，恰好污染我们要测的 Harness 变量
3. **版权与污染**：公开题库大概率进了各家产品的评测调优集（SWE-bench Verified 饱和、Verified→Pro 掉 48 分的教训）

**因此正确姿势：搬机制、搬题型结构、搬判分纪律；任务场景保持自研办公场景。**

## 3. 立即可搬的三条机制

### 3.1 负控制校验（源自 OpenBench 的 null adapter）
OpenBench 内置一个"什么都不做的假 harness"，应当判 0——用它验证判分器本身没有放水。
**我们的对应动作**：每题 checker 交付时，跑一次"空产物 + 随机垃圾产物"测试，必须判 0/低分。写进打分细则的 checker 验收条款。
### 3.2 真值后注入（源自 WildClawBench）
判分脚本与标准答案**绝不进入产品工作目录**，任务结束才落位。
**我们的对应动作**：cases 目录结构与 runs 快照规则中明确：`inputs/` 只含任务可见文件；checker 与标准答案放 `tasks/<批次>/<题>/grading/` 并在投喂时物理隔离（GUI 产品上传时只传 inputs）。
### 3.3 盲评（源自 Harness Arena）
复评者不知道产物出自哪款产品。
**我们的对应动作**：同学 20% 抽样复评时，产物文件脱去产品标识、打乱顺序后再给复评人。可并进打分细则的"评分者可信度"一节。

## 4. 回应"题目过于简单"：区分度诊断

批评部分成立，但要分清"哪种简单"：

- **T01 基线题的简单是故意的**（五款都该对，做不对本身就是发现）——保留
- **真正的风险是 OpenBench 的实测结论：简单任务上正确率会饱和，饱和后正确率失去区分度**。我们 90 次跑测里若一半题五款全对，那批跑测就浪费了

**逐题饱和度自检**（"全对风险"指五款产物分全满分）：

| 题 | 全对风险 | 兜底区分度 |
|---|---|---|
| T01 | 高（设计如此） | 行为分：主动确认/信息回传 |
| T02 | 中 | changes.md 覆盖率 + 可观测性 |
| T03 | 中 | index.md 行号引用对账（易错） |
| T04 | 中低 | 长文本截断处理差异 |
| T05/06/07 | 低（埋雷） | 三种行为分级本身就是分 |
| T08 | 中 | 越界检测（"过度热情"普遍） |
| T09 | 中 | 假设声明完整性锚点 |
| T10 | 中 | decision_log 质量锚点 |
| T11 | 中低 | 四重落点约束，GUI 类易落错 |
| T12 | 低 | 跨文件对账易漏 |
| T13 | 低 | 逐格对账，错误类型混合 |
| T14 | 低（埋雷） | 异常声明完整度 |

**改造原则：难度加在"执行结构"，不加在"知识难度"。** 同一份简单材料，区分度来自：多步依赖链（T03 式）、隐式约束（T08 式）、恢复陷阱（T05/06/07 式）、精确落点（T11 式）、自证回传（T02/T10/T14 式）——14 题的设计本来走的就是这条路，方向没错，但要在打分细则里补一条**饱和度预案**：

> 若某题五款产物分全部满分，则该题自动转入纯行为分/效率分判定（回合数、澄清次数、自查行为），并在数据表标注"正确率饱和"。

**效率分仅对可观测产品适用**（Codex/DSH 可看回合与 token；GUI 类记墙钟时间与澄清次数，且如实标注口径差异——口径差异本身是 Harness 设计差异，符合方案 §3 第 4 条）。

## 6. 2026-10-22 追加：WildClawBench `tasks/` 结构借鉴

> 触发：逐份阅读 `tasks/` 任务卡后确认——可搬的是**评测单元结构**，不是题库本身。
> 结论：搬 5 条结构机制，落点全部在 `docs/08 §8`；题库规模、容器隔离、模型排行榜不搬。

| 搬什么 | 落点 | 不搬什么 |
|---|---|---|
| 任务卡 YAML 头（`id/category/timeout/modality`） | `docs/08 §8.1` | 60 题规模、6 分类法 |
| `Expected Behavior` 与 `Prompt` 分离（人读 vs 投喂） | 沿用现有 `task.md` / `prompt.txt` 分离 | 容器内 `grade()` 全自动判分 |
| 多分项 metrics + `overall_score` | `docs/08 §8.2`（可选 `METRICS_JSON`） | Docker 逐题隔离 |
| Skills / Env / Warmup 声明式环境 | `docs/08 §8.4`"形态不支持"口径 | 同模型 × 多 harness 矩阵 |
| 单次运行证据包（`score/usage/log/task_output`） | `docs/08 §8.3` 三件套 | 模型排行榜 |
| 安全对齐题型（恶意技能注入 / 文档注入） | 待建 `S36`/`S37`，**不进 35 题主表** | 视频 / 多模态任务 |

§3.2 的"真值后注入"继续有效；桌面端无容器，以 `docs/08 §8.5` 的封存三步替代。
