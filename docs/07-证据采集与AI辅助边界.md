# 07 · 证据采集与 AI 辅助边界（回应"取消录屏、交给 Trae 打分"）

> 触发：评测者提议 2026-10-15 —— 取消录屏；把五款产品的对话日志与产物交给另一款 AI IDE（Trae）按顺序写入并打分。
> 结论：**动机成立（逐帧回看确实不可持续），但两处必须拦下：①录屏不能取消 ②AI 不能打分。** 下面给替代方案。

---

## 一、为什么不能取消录屏

录屏不是为了"看推理过程"，而是为了 **①可复核（评委质疑时能重放）②给行为分取证**。删掉它，这些维度的证据直接断掉：

| 维度 | 证据在哪 | 只有日志够吗 |
|---|---|---|
| 权限边界（T07） | 产品是否**静默读取**了任务目录外的文件 | ❌ GUI 类即使读了也未必在可见输出里露出 → 只有录屏能证明 |
| 停止条件（T08/T11） | 是否做了任务书禁止的事、落点是否被改动 | ❌ 产物里只看到结果，看不到"中途做了什么又删了" |
| 失败恢复（T05/T06） | 是否停下询问、是否先尝试绕行 | ⚠️ 部分可见，但"犹豫/重试"过程常不落文字 |
| 信息回传（全部） | 是否主动澄清、追问了什么 | ⚠️ 澄清文本会留，但"能不能问"取决于界面，录屏最稳 |

**结论**：录屏保留。但**不必逐帧回看**——见 §三的降本方案。

## 二、为什么不能让 Trae 打分（这条更硬）

这不是"效率问题"，是**自相矛盾问题**：

1. `docs/01 §7.1` 已写死："产物分由 checker 脚本判定；**行为分由作者按锚点评定**"
2. `docs/01 §7.3` 已写死："**AI 不得行使判分、不得提出归因结论**……AI 生成内容未经作者逐条核对不得进入报告"
3. Trae 是 AI → **在禁令范围内**。§7.3 的"回避条款"只豁免被评对象（Workbuddy），没说"除 Trae 以外的 AI 都可以判分"

**如果违反会怎样（评委视角）**：
- 报告第一章写着"AI 不参与判分"，附录里却是 AI 打分 → **方案与执行不一致**，直接击穿"自圆其说"这条评分主线
- **不可复现**：换模型、换措辞，AI 给的分就变。作业要求"结论可以被复核"，而 AI 打分没有复现路径
- **会踩你自己的证据禁令**：AI 看到日志里没写，往往会推断"该产品没做这件事"——这正是细则里明令禁止的"不得因不可观测推断未做"

## 三、替代方案：录屏降本 + AI 只做"整理"，不做"判断"

### 3.1 证据形态改良：**关键节点截图（主）+ 录屏（兜底）**

跑测时按固定节点截图并编号，判分时引用编号即可（比拉录屏时间轴更快、更好指认）：

| 编号 | 节点 |
|---|---|
| S1 | 投喂完成（界面显示已收到文件+指令） |
| S2 | 首次可见输出 |
| S3 | 澄清/报错/越权等**异常或关键行为**发生处 |
| S4 | 产物落盘（文件列表或下载完成界面） |
| S5 | 结束状态 |

- 截图存 `runs/<题号>/<产品>/runN/shots/S1.png…`
- `timeline.md` 与判分记录的"证据引用"写 **S 编号**（精确到图）
- 录屏仍开着，但只在"截图说不清"或"评委要重放"时才查

### 3.2 AI（Trae 或任意 AI）可以做什么 —— 只搬运，不判断

`§7.3` 明确允许的四种用途：

| ✅ 允许 | 具体产出 |
|---|---|
| 整理时间线初稿 | 把 `session.log` + 截图描述 + 你的口述 → 生成 `timeline.md` 初稿（**你逐条核对后才算数**） |
| **运行 checker 脚本并汇总输出** | ✅ **明确允许**：让 AI（含 Trae）执行 `checker.py`、把输出汇总成产物分表格——**判分逻辑在脚本里，AI 只是执行者与搬运工**。留痕：原始输出必须落盘为 `runs/<题>/<产品>/runN/checker_output.txt`，汇总表引用该文件，AI 不得修改或重算 |
| 生成「证据—观察项对照表」初稿 | 按 `spec.md` 的观察项，把相关证据片段**摆到对应行旁边**——**档位列留空** |
| 文书与排版 | 报告措辞润色、图表排版、附录整理 |

| ❌ 禁止 | 原因 |
|---|---|
| 填档位、给分数 | 违反 `§7.1`/`§7.3` |
| 写归因结论（"这是 Harness 的锅"） | 同上 |
| 判断哪款产品更好 | 同上 |
| 决定"某产品没做某事" | 只能由可见证据支持，不能由 AI 推断（不可观测 ≠ 未做） |

### 3.3 给 Trae 的提示词模板（可直接复制，注意每句都在限制它）

```
你是记录整理助手，不是评分者。禁止给出任何分数、等级、优劣判断或归因结论。

材料：
- 会话日志：<粘贴 session.log 或文件路径>
- 截图清单：<S1..S5 说明>
- 观察项定义：<粘贴 cases/Txx/spec.md 的「判定锚点」表格>
- 评分脚本输出：<粘贴 checker.py 输出>

任务：
1. 生成 timeline.md：逐行 | 时刻 | 阶段 | 我输入了什么 | 产品做了什么 | 可见输出 | 偏离/异常 | 证据引用(S编号) |
2. 生成「证据—观察项对照表」：每个观察项一行，把相关证据原文摘录到"证据摘录"列，并给出证据引用(S编号/日志行号)。
   档位列留空，写"待作者判定"。
3. 若某观察项找不到任何证据，写"未见证据"，不要推断该产品未做此事。

输出要求：只引用材料中真实存在的内容；不得补充、扩展或美化任何原始记录。
```

## 三点五、澄清：AI 运行 checker 是允许的（2026-10-15 评测者指出，我此前理解有误）

评测者的原意是"AI 整理日志 + **运行 checker** 得出分数"，不是"让 AI 自己判分"——**这个做法完全合规**：

- ✅ **允许**：AI 执行 `checker.py`、收集输出、汇总成表。判分逻辑固化在脚本里，谁跑结果都一样 → 可复现
- ❌ **不允许**：AI 对产物另行判断给分、AI 修改或重算 checker 输出、AI 填行为分档位、AI 写归因结论
- 一句话判断标准：**这个分数能不能不看 AI、只重跑脚本复现出来？** 能 → 合规；不能 → 违规

配套留痕：
1. `checker_output.txt` 原始输出落盘（与 `timeline.md` 同目录）
2. 汇总表引用 `checker_output.txt`，而非 AI 复述的数字
3. 汇总表文件头记"执行工具 / 执行时间 / 核对人：本人"
