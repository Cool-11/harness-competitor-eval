# 08 · 目录与命名规范

> 触发：2026-10-16 整理前，仓库出现三层投喂副本（`cases/<题>` / `inputs/` / `inputs-txt/` / `cases/all-inputs/`）互相打架，其中 `cases/all-inputs/` 混入 2 个旧版本文件，取件时可能拿错导致实测作废。
> 结论：**真源唯一、取件处只读、现场不改写、留档可回滚。** 本规范固化整理后的口径，后续新增内容一律照此执行。

---

## 一、四层职责（谁是真源，一句话讲清）

| 层 | 目录 | 职责 | 能否直接编辑 |
|---|---|---|---|
| **真源** | `cases/<题号>/` | 唯一权威内容：`task.md` · `prompt.txt` · `inputs/` · `checker.py` · `spec.md` | ✅ 只能改这里 |
| **取件** | `cases/all-inputs/` | 投喂文件的扁平取件副本 | ❌ 只读，从真源同步 |
| **现场** | `runs/` | 实测记录：时间线 · 日志 · 产物 · 录屏链接 | ⚠️ 只追加，不改历史 |
| **留档** | `_archive/` | 整理前快照 + 路径迁移记录 | ❌ 只读，不入 git |

**判断口诀**：要改内容 → 改 `cases/<题号>/`；要拿文件投喂 → 从 `cases/all-inputs/` 取；要记结果 → 写 `runs/`。

## 二、目录命名规范

### 2.1 题库

```
cases/<题号>-<英文slug>/
  例：cases/T00-hello-world/ · cases/T14-silent-anomaly-trap/
```

- 题号：`T` + 两位数字（校准题用 `T00` / `T00b`），保持**两位定宽**便于排序
- slug：全小写英文 + 连字符，概括考点（`contradiction-trap` 而非 `trap2`）
- 模板目录固定为 `cases/_template/`，下划线前缀表示"非正式题"

### 2.2 现场

```
runs/<题号>/<产品>/run<n>/
  例：runs/T05/yuanbao/run2/
```

- **产品名固定五个 slug，不得简写**：`codex` · `dsh` · `workbuddy` · `yuanbao` · `doubao`
  - ❌ 禁止 `wb` / `yunbao` / `元宝` / `Workbuddy` 等变体（2026-10-16 已统一）
- `run<n>` 从 `1` 起，不留前导零
- 每个 run 目录固定四件套：`timeline.md` · `session.log` · `artifacts/` · `shots/`，另加 `recording.txt`
- 埋雷题（T05/T06/T07/T14）每产品两个 run，其余一个

### 2.3 非标准现场

确有不能套用 `<题号>/<产品>/run<n>` 的批次（如跨题日志分析），集中放在 `runs/` 下**单一名目录**，并在 `runs/README.md` 登记说明：

```
runs/Five-app-log-analyse/<产品>-log-analyse/   ← 产品名仍须符合 §2.2 口径
```

### 2.4 其他固定目录

`docs/` · `scripts/` · `runs/baseline/`（基线 + 回滚包）· `_archive/`（留档）· `cases/_template/`

## 三、文件命名规范

| 类型 | 规范 | 示例 |
|---|---|---|
| 题库四件套 | **固定小写名，不得改动** | `task.md` · `prompt.txt` · `checker.py` · `spec.md` |
| 机读真值 | 固定名 | `truth.json` |
| 判分表 | 固定名 | `判分记录表.md` |
| 现场记录 | 固定名 | `timeline.md` · `session.log` · `recording.txt` |
| 投喂指令副本 | `<题号>-<slug>_prompt.txt` | `T01-meeting-notes_prompt.txt` |
| 文档 | `<两位编号>-<名称>-v<版本>.md` | `01-评测方案-v1.md` · `08-目录与命名规范.md` |
| 周报 | `周报<两位序号>-<MMDD>-<状态>.md` | `周报01-1017-草稿.md` |

### 3.1 投喂附件为什么是中英混用（不是错误，别改）

`cases/<题号>/inputs/` 里的附件名（`合同-A.md`、`会议纪要-1.md`、`background.md`…）**被任务书逐字引用**：

```
prompt.txt：请阅读附件 `会议纪要-1.md` …
```

改名必须同步改 `task.md` + `prompt.txt` + `spec.md` + `checker.py` 里的引用，且已跑过的 `runs/` 记录会全部失配。**因此附件名按"创建即冻结"处理，不做规范化重命名。**

## 四、投喂纪律（唯一口径）

1. **新开会话**：每题独立会话，五款同一规则
2. **附件**：只挂本题 `inputs/` 里的数据文件（1~12 个），文件从 `cases/all-inputs/` 取
3. **指令**：把该题 `prompt.txt` 的正文**复制粘贴**到对话框，作为消息文字
4. **绝不投喂**：`task.md` · `spec.md` · `truth.json` · `checker.py`（泄题 / 泄真值）
5. **绝不整体投喂** `cases/all-inputs/`：46 个文件混投会让题目失去指向、破坏题间隔离
6. **投喂前记哈希**：`sha256(prompt.txt)` 与 `sha256(inputs/*)`，与 `timeline.md` 表头核对

## 五、文档格式规范

所有 `docs/*.md` 统一结构：

```markdown
# <编号> · <标题>

> 触发：<为什么写这份>
> 结论：<一句话给出判断>

---

## 一、<节>
## 二、<节>
```

- 标题用 `# 编号 · 标题`（全角间隔号）
- 用 `>` 引用块写"触发 / 结论"，让读者 5 秒抓住要点
- 用 `---` 分隔元信息与正文
- 表格优先于长段落；锚点/判据一律**编号**（`§5.2`、证据⑧）便于交叉引用

## 六、变更纪律

| 变更类型 | 正确动作 |
|---|---|
| 改题目内容 | 改 `cases/<题号>/` 真源 → 同步 `cases/all-inputs/` → 记 `sha256` |
| 改已跑完的现场 | **不改**。新增 `timeline.md` 补注或另起 run |
| 改历史日志/判分输出 | **绝不改**（属原始证据）；如路径失效，写进 `_archive/README.md` 的路径迁移记录 |
| 移动仓库位置 | 移动后更新 `_archive/README.md` 的路径迁移表，并在 `runs/README.md` 提示旧绝对路径 |
| 整层目录结构变动 | 先把原目录复制进 `_archive/<日期>-整理前快照/`，校验一致后再动 |

## 七、整理后的自检清单

每次新增或整理后跑一遍：

```bash
# 1. all-inputs 与真源逐字节一致？
for s in cases/*/inputs/*; do cmp -s "$s" "cases/all-inputs/$(basename "$s")" || echo "不一致: $s"; done
for d in cases/T*/; do t=$(basename "$d"); cmp -s "$d/prompt.txt" "cases/all-inputs/${t}_prompt.txt" || echo "不一致: $t"; done

# 2. 产品目录口径是否统一（应只有五个）
find runs -maxdepth 2 -mindepth 2 -type d -not -path "*baseline*" | sed 's|.*/||;s|-log-analyse||' | sort -u

# 3. 现场目录是否齐备（每题 × 五产品；cases 用长名，runs 用短题号，需截断）
for t in cases/T*/; do n=$(basename "$t"); case "$n" in _template|all-inputs) continue;; esac
  id=${n%%-*}   # T01-meeting-notes → T01
  for p in codex dsh workbuddy yuanbao doubao; do [ -d "runs/$id/$p" ] || echo "缺: runs/$id/$p"; done; done
```
