## 1. 统一失败表（两轴）

一个失败由**两个坐标**共同定位：**A 轴说"它怎么结束的"，B 轴说"推理在哪里断的"**。二者互补——A 轴可自动判（异常/预算/声明），B 轴要读产物与轨迹。

### 1.1 A 轴 · 终止机制（源自 Scaffold Effect 附录 A，异常优先）

判定**严格按顺序**，先命中先归类：

| 序 | 条件 | 编码 | 含义 |
|---|---|---|---|
| 1 | 有异常 | `A6 ERROR` / `A5 HANG` / `A4 TIME` | `AgentTimeoutError`→`A4`；`NonZeroAgentExitCode`/`AgentSetupError`→`A5`；`EnvironmentBuild`/`RewardFileNotFound`/parse→`A6` |
| 2 | `solved=true` | `A0 SOLVED` | 通过 |
| 3 | `hit_turn_budget=true` | `A3 MAX_TURNS` | 耗尽迭代预算（仅暴露 turn-budget 的产品会产生） |
| 4 | `finish_called=true` | `A2 VERIFY` | **自称完成，但外部校验失败** |
| 5 | 其余 | `A1 REASON` | **未声明完成即自愿停手** |

**指纹示例**（Scaffold Effect 实测）：Goose=`A1 REASON` 主导（干净认输）；OpenHands-SDK=`A2 VERIFY`+`A3 MAX_TURNS`（求收尾、接受貌似合理的错解）；OpenCode=`A4/A5`（无 turn-budget，耗光墙钟）。**指纹跨两个模型复现 → 归 scaffold 而非 model。**

### 1.2 B 轴 · 失配位点（源自 Harness-Bench §5.1，按"轨迹在哪失去与成功条件的对齐"）

| 编码 | 位点 | 占失败轨迹 | 含义 |
|---|---|---|---|
| `B1` | Contract / format | **36.4%** | schema/输出契约违规（JSON 畸形、缺行、manifest 不全） |
| `B2` | Tool / recovery | **24.6%** | 工具报错或命令被拦后，**无有效恢复或改计划** |
| `B3` | Evidence / grounding | **14.6%** | 来源覆盖不全、unsupported claims |
| `B4` | Artifact commitment | **11.1%** | 推理合理但**没提交必需产物** |
| `B5` | State / continuation | **9.3%** | 多轮/中断任务未保存进度、续接不可靠 |

> Harness-Bench §5.2 定义 **Execution Alignment** = harness 维持「推理—工作区状态—工具动作—评估者校验条件」四者对应的程度；对应关系断裂即失败（四类脱节：工具反馈未并入下一步 / 证据未绑定 claims / 部分进度未保存 / 意图结果未提交为有效产物）。

### 1.3 两轴乘积 → 失败编码

**编码格式**：`A<机制>-B<位点>`，例如：

| 编码 | 读法 | 通俗说法 |
|---|---|---|
| `A2-B4` | 自称完成 × 产物未提交 | **伪装成功** |
| `A1-B2` | 停手 × 工具恢复 | 卡住即放弃 |
| `A3-B5` | 耗尽迭代 × 状态续接 | 长篇空转、进度丢失 |
| `A0-—` | 通过 | 成功 |

**这个乘积直接给出"沉默失败 vs 错误型"的界线**（对齐 `docs/09 §6.1` 的 L 阶梯）：

- `A1 REASON` / `A3 MAX_TURNS` / `A4 TIME` / `A5 HANG`（**无声/非声明结束**）→ **L0 沉默失败**（最危险）
- `A2 VERIFY`（**出声但错**）→ **L1 错误型**

> ⚠️ **跨产品同款复现 ≠ 自动归 Harness，也 ≠ 题目歧义**——它只是"该动手查"的信号，三种成因须互证区分：**(a) 题目歧义 / (b) 真值(oracle)错 / (c) 共同 Harness 弱点**（判别见 §3.1 第⓪.5步）。把 (b)(c) 误判成 (a) 会丢掉最值钱的"共同弱点"——这是本表最容易被误用的一处。

### 1.4 两轴 → 7 观测维度 → 9 零件（归因搜索空间）

| B 位点 | → 观测维度 | → 主责零件 |
|---|---|---|
| `B1` Contract/format | D2 产物落点 | **P5** 产物落盘 |
| `B2` Tool/recovery | D3 失败恢复 · D5 停止条件 | **P6** 错误恢复 · P7 护栏 |
| `B3` Evidence/grounding | D1 信息回传 · D7 可观测性 | **P8** 遥测 |
| `B4` Artifact commitment | D2 产物落点 | **P5** 产物落盘 |
| `B5` State/continuation | D4 上下文管理 | **P4** 上下文管理 |

> 旧 `F-D1..F-D7` 编码降级为 **B 轴位点的中文注脚**，不再单列。任何成体系的失败编码必须**可跨产品/跨题聚合**——B 轴已带文献占比，直接支持聚合。

## 2. 可换零件清单（P1–P9 → DSH 真实 seam）

> 源自 `dsh/docs/capability-seams.md` 的 Role 列（**core / seam / bundle / service**）与 `architecture.md`（"Every part is a plugin… replaceable from configuration"；`dsh --profile web --dump-config` 打印可 patch 的每一行）。
> **换件可行性分级**：**S = 有多实现 provider，profile 换 provider 即可** ｜ **C = 单实现，可通过 profile patch 改配置行，改行为需自写 provider** ｜ **B = bundle 组合点，替换牵动整棵子树**。

| 零件 | DSH `ctx.*` | Role | 换件级 | 换法（一次只动一处） |
|---|---|---|---|---|
| **P1** 编排 | `ctx.agentLoop` ｜ `ctx.systemPrompt` ｜ `ctx.agentPresets` | bundle ｜ core ｜ core | **B/C** | patch 换 agentLoop bundle；systemPrompt 注册式替换；agent preset 换能力集 |
| **P2** 工具接口 | `ctx.tools`（+ `tool-*` 插件） | core | **C/S** | 增删 `tool-*` 插件（工具集）；pipeline 本体改行为需 patch |
| **P3** 文件/沙箱 | `ctx.fs` ｜ `ctx.subprocess` ｜ `ctx.shell` ｜ `ctx.sandbox` | **seam** ×4 | **S** | 换 provider：`fs-local`↔`fs-sandbox`↔`fs-ssh`；`sandbox-local`↔`sandbox-ssh` |
| **P4** 上下文 | `ctx.compaction` ｜ `ctx.toolResultPruner` ｜ `ctx.tokenMeter` | **seam** ｜ core ｜ core | **S/C** | 换 `compaction-basic`；调 pruner/tokenMeter 参数 |
| **P5** 产物落盘 | `ctx.fs` ｜ `workspace-changes` ｜ `api-workspace-files` | **seam** ｜ core ｜ core | **S/C** | 随 `ctx.fs` provider；workspace 视图 core |
| **P6** 错误恢复 | agent-loop 重试 ｜ `ctx.compaction` 的 request-error recovery | bundle ｜ seam | **B/S** | 换 compaction seam；重试策略在 agent-loop（bundle） |
| **P7** 终止护栏 | `agent/turn-stopping`（serial）｜ `ctx.planMode` | bundle ｜ core | **B/C** | turn-stopping 挂在 agent-loop；planMode core |
| **P8** 遥测 | `ctx.sessionTelemetry` ｜ `ctx.otel` ｜ `ctx.productTelemetry` | **seam** ｜ service ｜ service | **S/C** | 换 `session-telemetry-otel`；关/开遥测通道 |
| **P9** 权限 | `ctx.approval` ｜ `ctx.sandboxPolicy` ｜ `ctx.permissionPresets` | **seam** ｜ core ｜ core | **S/C** | 换 approval 实现；改 preset（`workspace-write`↔`danger-full-access`，一次切一个旋钮） |

**阶段 0 结论**：**P3/P8 是纯 S 级（配置即换，最干净的对照组）**；**P4/P5/P9 是 S/C 混合**；**P1/P6/P7 是 B 级（改行为要动 bundle）** → **换件实验优先从 S 级零件入手**（P3 文件沙箱、P8 遥测、P9 权限 preset），先把"A 级因果"打出来，再攻 B 级。

**纪律**：`ctx.sandboxPolicy` 明确"**只有 sandboxed executor 与 provider 读它，bash 与 fs 不能 confine 到不同 root**"——所以 P3/P9 联动改动会**同时**动到 bash+fs，**不算"只改一处"**；换 P3 时须固定 P9，反之亦然（这正是"控制变量洁癖"要盯的耦合点）。

## 3. BadCase → 三句话 判定卡

### 3.1 判定流水线（严格顺序）

**第⓪步 · 前置闸门（跑测前做，不在跑测后补判）：题目有效性。** 歧义审查 + 可判性 + **真值自洽**（Harness-Bench 的 realism / solvability / oracle-checkability 三重审查即此）。任一不过 → 改题/oracle（登记制），该题不进入归属。

**第⓪.5步 · 归属判别（三步互证——决定"这到底是不是 Harness 的事"）。** 拿到一个失败后，按序：

1. **发散 / 收敛**：产品们**解读发散**（各给不同答案）→ **(a) 真·题目歧义** → 改题，不记账；产品们**解读收敛**（同样的错答案）→ 进 2。
2. **真值是否自洽**：产物**符合任务书字面**、真值/checker 却判错 → **(b) 真值/oracle 错** → 修 oracle，**任何产品与 Harness 都不记账**（T02 即此类，见 §6）；字面与真值同指一个答案、产品却错 → 进 3。
3. **裸模型探针裁决**（Tier 0）：探针**能做对** → 字面清晰、模型有能力 → **(c) 栽在 Harness（系统性）→ 保留，这是高价值发现**；探针也做错同样 → 题面本身难/歧义 → 回 1。

> **纪律**：「跨产品复现」只是**"该动手查"的信号，不是"题目歧义"的判决**；判决必须走完 1→2→3 互证。把 (b)(c) 误判成 (a)，会丢掉最值钱的"共同弱点"，且触发"不为分数好看改标准"的红线。

**第①句：是不是 Harness 的锅？**（排除模型）
- 裸模型探针（`Tier 0`）：任务书直接给裸 LLM——若**模型本身能做知识部分**而产品失败 → 倾向 Harness；
- 条件对照（`Tier 2`）：同题只换一个输入条件——若**该条件下稳定失败、另一条件下通过** → 倾向 Harness；
- 换件对照（`Tier 1`，仅 DSH）：只改一处零件——若失败**随之消失** → **确认 Harness（A 级）**。
- 若三层都指向模型本身 → **如实写"这不是 Harness 的锅"**（这本身是高分项）。

**第②句：哪个零件？**
- 由**B 轴位点**查 §1.4 映射到主责零件，**A 轴机制**佐证（如 `A2 VERIFY` 强化"产物/契约"嫌疑）；
- 换件实验证实 → 锁定零件；不能换件的产品 → 标"倾向零件 + 证据不足"。

**第③句：证据多硬？**
- 标 **A / B / C** 等级（`docs/01 §4.2`）：A=换件实测因果 ｜ B=探针/条件推断 ｜ C=指纹跨产品复现；
- 主结论带**置信区间**（仅双跑可报，单跑不硬造 CI）；
- **闭环复测**：改件后该编码消失 → A 级成立；失败照旧 → **假设被证伪，如实记录**。

### 3.2 判定卡模板（每个 BadCase 一张，跑测前冻结格式）

```markdown
### BC-<编号> ｜ 题：S__ ｜ 产品：<型号+版本> ｜ runN
- **现象（一句话）**：
- **A 轴 终止机制**：A_（REASON/VERIFY/MAX_TURNS/TIME/HANG/ERROR）→ 沉默失败(L0)/错误型(L1)
- **B 轴 失配位点**：B_（Contract/Tool-Recovery/Evidence/Artifact/State）
- **失败编码**：`A_-B_`
- **第①句 是不是 Harness**：<是/否/证据不足> ｜ 依据：探针__ / 条件__ / 换件__
- **第②句 哪个零件**：P_（主责）｜ 次责：P_ ｜ 证据：
- **第③句 证据多硬**：等级 A/B/C ｜ 复现率 __ ｜ 反证检查：__
- **证据引用**：<文件> L# / rec mm:ss
- **闭环节点**：待 §CL__ 复测
```

## 4. 严格执行的纪律（红线，抄自公告）

1. **控制变量洁癖**：一次只动一个地方。绝大多数失败的评测不是方法不对，是顺手改了别的东西（例：改 P3 时必须冻结 P9，见 §2 耦合点）。
2. **先冻结尺子再出题**：`docs/03`（含本失败表 + DSH `testing.md` 三纪律）升 **v1 冻结**，**先于任何 S 题实体**——这是 `docs/00 §L5` 的硬红线。
3. **敢说"证据不够"**：分不清就标"仅观察"，比硬编一个结论有价值得多。
4. **checker 三纪律**（抄自 DSH `testing.md`）：**验外部产物而非自述**（对外部复算，不信 Agent 自称）｜**负控制必须能变红**（引入回归看它失败）｜**测真实产物路径**（不测 mock）。
5. **holdout 盲判**：成功判据（10 个未见 BadCase ≥7 定位到零件）用**未参与设计**的 BadCase 盲判计分（来源计划见 §5）。

## 5. holdout BadCase 来源计划（"未见"怎么算数）

"不见过"必须可证：设计 S 题时**不使用**它们。三条来源，按可证实性排序：

1. **既有 100 次 runs 中的失败**（`Log-analyse/` 已跑）——它们服务于旧 T 题库，**未参与新 S 题设计** → 可作 holdout（证据强：时间戳在先）。
2. **他人/另一 Agent 生成的 BadCase**——委托者不告知设计意图 → 真"未见"。
3. **跑测后逐次记录的新 BadCase**——留出**最后 N 次**不纳入设计。

> 判定登记：每个 holdout BadCase 记录"来源 + 为何算未见 + 备好答案与否"，防止事后把设计内的案例冒充未见。

**验证结论（真实数据，2026-10-17 更新）**：

1. **两轴表能干净分类真实失败**——3/3 真实失败（§6 表 2–4 行）无需改两轴定义。
2. **T02 反例推翻了我原来的粗规则**：T02「去重失败」在 codex / dsh / 元宝三款同款复现（`codex-log-analyse/checker_output-full.txt:46`、`dsh-log-analyse/checker_output.txt:45`、`yuanbao-log-analyse/checker_output.txt:57`）。追查发现：题面只要求删「**完全重复**」的行，而李娜/吴敏**姓名不同**、并非完全重复；五款按字面保留两行（11 行）却被真值判错。**结论：这是 (b) 真值/oracle 错，不是 (a) 题目歧义。** 已于 2026-10-17 按登记制修 oracle（真值 10→11 行），复检后 DSH/元宝 T02 由 4.5/7 → **7/7 PASS**，题面不变。→ 据此把 §3.1 改为"三步互证"，废弃"跨产品复现→题目歧义"的粗规则。
3. **A 轴真实分布：`A2 VERIFY` 占 3/3（真实失败样本）**——失败者都**声称完成却没达标**，正是公告要盯的"伪装/沉默失败"，与本设计重心一致。
