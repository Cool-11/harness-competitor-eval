# 12 · 批量日志接收与时间线补全（AI 协作口径）

> 触发：2026-10-21 确定改为"全量批次跑 + 跑完交日志"的工作方式，需要把"交什么、缺什么、谁补"写成固定规则。
> 结论：**AI 负责比对与起草，作者负责判定与补缺**。AI 不填分数、不写归因、不推断"产品没做某事"。

---

## 一、批量交付的最小包（缺一即视为不完整）

每次批量跑完，按**产品 × 轮次**交一个包：

```
Log-analyse/<产品>-log-analyse/
├── artifacts/second-run-artifact/<题号>/     # 产物快照（整目录）
├── artifacts/second-run-artifact/shots/<题号>/S1..S5.png
├── artifacts/second-run-artifact/recording/  # 产品输出日志（txt / csv / md）
└── session.log                               # 可见输出原文（未整理）
```

配套单次元信息（每题一行）记在 `timeline.md` 或直接贴在交付消息里。

---

## 二、我收到日志后会自动核对的 13 项

对照 `docs/05 §一` 的关键信息清单，我逐项判断"已提供 / 缺失 / 矛盾"，**只问缺的和冲突的**。

| # | 字段 | 我从哪里判断 | 缺失时我会问 |
|---|---|---|---|
| 1 | 题号 / 产品 / 运行序号 | 目录名 | "这批覆盖哪几题？run1 还是含 run2？" |
| 2 | 日期与起止时刻 | timeline / 日志时间戳 | "起止时刻分别是？" |
| 3 | 产品版本号 / 账号状态 | timeline 头 | "版本号是多少？账号/会员档位有无变化？" |
| 4 | 任务书 sha256 前 8 位 | timeline 头 | "prompt.txt 的哈希有没有记录？" |
| 5 | 投喂方式 | timeline / session.log | "上传还是放工作目录？任务指令是粘贴正文吗？" |
| 6 | 墙钟耗时 | timeline | "本题耗时大约几分钟？" |
| 7 | 澄清次数与内容 | session.log | "它问过什么？你回了什么？" |
| 8 | 产物清单（含多余产物） | artifacts 目录 | "有没有产物落在 artifacts 外？" |
| 9 | 异常与偏离 | session.log / 你的口述 | "有没有卡死、重试、超时、越权？" |
| 10 | 录屏链接 + 校验码 | recording.txt | "录屏链接和时长？" |
| 11 | checker 结果 | `checker_output.txt` | **我来跑**，不用你给 |
| 12 | 行为分 | 由作者填 | 不询问；AI 不填档位 |
| 13 | 判分 / 复评时间 | 判分表 | "首评和复评时间？（间隔须 ≥12h）" |

**批量层面另问 5 项**（每批一次）：

1. 这批是**同一会话连续跑**，还是每题新开会话？
2. 共开了几个会话、工作目录是不是每 run 独立？
3. Codex 是否用了独立 `CODEX_HOME`？路径是什么？
4. GUI 产品有没有遇到上传数量/字数限制？
5. 有没有题因产品能力限制无法完成投喂（如实记录，不算失败）？

## 三、`timeline.md` 补全提醒

### 3.1 必填表头

| 项 | 要求 |
|---|---|
| 题号 / 产品 / 运行序号 | 与目录名一致 |
| 日期与起止时刻 | 精确到分钟 |
| 产品版本号 / 账号状态 | 版本必须写；账号状态写"默认/关闭记忆"等 |
| 任务书 sha256 前 8 位 | 证明五款同版 |
| 投喂方式 | 上传 / 放目录 / 粘贴正文 |
| 墙钟耗时 | 分钟 |
| 澄清次数 | 次数 + 每次问答原文 |
| 新开会话 | 是 / 否（否必须标为可比性缺陷） |

### 3.2 时间线六个必备节点

| 节点 | 记什么 |
|---|---|
| 投喂完成 | 你发了什么、附件数量 |
| 首次可见输出 | 第一个可观察动作 |
| 首次动产物 | 第一次写文件/下载 |
| 异常发生 | 报错、卡顿、越权、拒答 |
| 产物落盘 | 文件名 + 落点 |
| 结束 | 它说完成 / 你终止 |

### 3.3 证据引用优先级（写不出引用的分数无效）

```
原始结构化 trace（Codex rollout / DSH 遥测）
  > 截图编号 S1–S5
  > 录屏 rec mm:ss
  > session.log 行号
  > 产物反推（仅兜底）
```

### 3.4 三条禁令

1. **不把自述当事实**：日志里说"未读取外部文件"，只能记作"声称"，需与产物/截图交叉验证。
2. **不因不可观测推断未做**：看不到就写"不可观测 / 未见证据"。
3. **不改写历史日志**：补全只写 `timeline.md`，不动 `session.log` / `checker_output.txt`。

## 四、shots 与 recording 的放置

| 目录 | 放什么 | 命名 |
|---|---|---|
| `artifacts/<轮次>/shots/<题号>/` | S1–S5 关键节点截图 | `S1.png` … `S5.png` |
| `artifacts/<轮次>/recording/` | 产品输出日志副本 | `<产品>_<题号>_<日期>.txt/csv/md` |
| `<产品>-log-analyse/session.log` | 该批可见输出原文 | 固定名 |

> 你只需告诉我"这些截图属于哪款产品、哪道题"，我按顺序命名归位；**不替你判断截图内容对错**。

## 五、我的职责边界（摘要）

| 我做 | 我不做 |
|---|---|
| 核对交付包完整性、列出缺失项 | 填行为分档位 |
| 运行 `checker.py` 并落盘原始输出 | 改判 checker 结果 |
| 起草 `timeline.md`（你逐条核对） | 写归因结论 |
| 生成"证据—观察项对照表"（档位列留空） | 判断"某产品没做某事" |
| 按你指定的产品/题号给截图命名归位 | 决定截图代表什么行为 |

依据：`docs/07`、`docs/03 §2.3`、`docs/01 §7.3`。
