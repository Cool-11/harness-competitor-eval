# 15 · S06 试点运行卡 v0.1

> 目的：用 `S06-artifact-deep-path` 一道题 × 五款产品 × 各 1 次，验证“计划 → 跑测 → 归档 → 判分 → 聚合”整条管线；**试点不用于五款排名**。
> 结论：**产品只在临时工作目录干活；证据只落 `Log-analyse/S-batch/`；返回给评测者/复核者的是“路径 + 证据包”，不是整个临时目录。**
> 依据：`docs/14` 的 chapter7 评估体系（四环节 + Rubric + 首错归因 + 统计），以及 `docs/08 §8` 的运行证据规范。
> **2026-10-23 口径变更**：`recording.txt` 改为**产品外部日志**（工具调用/运行时/错误栈），不再记录录屏链接；本轮不要求录屏。

## 0. 一句话

**五款各跑 1 次；每款一个新会话、一个独立工作目录；产物/日志/截图归档到 `Log-analyse/S-batch/S06-artifact-deep-path/<product>/run1/`；`F:\tmp_run\...` 只用于跑测，不进仓库。**

## 2. 三个位置：临时目录、证据目录、投喂目录

| 位置 | 用途 | 是否进 git |
|---|---|---|
| `F:\tmp_run\S06-artifact-deep-path\<product>\run1\work` | 产品实际干活的工作目录 | ❌ 不进 |
| `F:\tmp_run\S06-artifact-deep-path\<product>\run1\prepare.json` | 开始时间、prompt/inputs 哈希 | ❌ 不进，但**复制进证据包** |
| `Log-analyse/S-batch/S06-artifact-deep-path/<product>/run1/` | 证据包（产物、日志、截图、判分） | ✅ 进（视频除外） |

投喂来源：

- 输入文件：`tasks/second_tasks/S06-artifact-deep-path/inputs/notes.md`
- 指令文本：`tasks/second_tasks/S06-artifact-deep-path/prompt.txt`
- **绝不投喂**：`task.md`、`spec.md`、`truth.json`、`checker.py`

## 3. 证据包固定结构

```
Log-analyse/S-batch/S06-artifact-deep-path/<product>/run1/
├── timeline.md              # 执行时间线（当天补完）
├── session.log              # CLI 全量终端输出；GUI 导出的对话记录
│                            # 若 GUI 无导出，则 session.log/ 为截图目录
├── artifacts/               # 工作目录完整快照（含多余/落错文件，不改）
├── shots/                   # S1–S5 关键节点截图
├── recording.txt            # 产品外部日志（工具调用/运行时/错误栈）；不再放录屏链接
├── prepare.json             # 开始时间 + prompt/inputs 哈希（从临时目录复制）
├── checker_output.txt       # checker 原始 stdout/stderr，不改写
├── manifest.json            # 题/产品/run/起止/哈希/产物数/exit/干预/rerun
├── usage.json               # 墙钟秒数/turns/timed_out/人工干预
├── score.json               # raw_got/raw_full/metrics/failure_code/evidence_grade/status
├── run.json                 # v2：终止原因、绑定、评分、首错、证据
├── grade.yaml               # v2：人工 Rubric 分 + 每格证据引用
├── 判分记录表.md            # 可选：人读版判分表
└── badcase.yaml             # 可选：失败才建；首错步骤/根因/后果/置信度
```

任务级汇总：

```
Log-analyse/S-batch/S06-artifact-deep-path/
├── pilot-summary.md         # 五款覆盖、成功率、v1 明细、失败编码、局限
└── pilot-results.json       # 机读聚合（5 条 run 的汇总）
```

### 3.1 每个文件写什么

| 文件 | 必填内容 | 不要写什么 |
|---|---|---|
| `timeline.md` | 时刻、阶段、输入、产品动作、可见输出、偏离/异常、证据引用（S1–S5 / session.log L# / recording.txt L#） | 事后推测、没有证据的判断 |
| `session.log` | CLI 全量输出；GUI 导出对话 | 截断、只留成功片段、改写原始日志 |
| `artifacts/` | 整个工作目录原样复制；落错路径/多余文件也保留 | 替产品修正路径、改名、删除多余产物 |
| `shots/` | S1 投喂完成 / S2 首次输出 / S3 澄清·报错·越权 / S4 产物落盘 / S5 结束 | 只截最终结果 |
| `recording.txt` | 产品外部日志：工具调用/运行时/错误栈/导出日志；无则写“产品未提供外部日志” | 录屏链接、视频文件；不要只把日志发到对话里而不落盘 |
| `prepare.json` | 开始时间、prompt sha256[:8]、inputs sha256[:8] | 事后补编时间 |
| `checker_output.txt` | checker 原始输出 | 手工改分、删失败项 |
| `manifest.json` | 题名、产品、run、起止、哈希、产物数、exit、干预、rerun | 空字段 |
| `usage.json` | 墙钟秒数、turns、timed_out、manual_interventions | 把秒数当分数 |
| `score.json` | raw_got/raw_full、metrics、failure_code、evidence_grade、status | 未判就填 graded |
| `run.json` | 由 `prepare` 生成骨架、`collect` 回填终止/绑定/components/success/证据；人工补 `first_error` / `evidence_grade` / `v1` | 只写最终分数 |
| `grade.yaml` | 每个观察格的档位、证据引用、备注 | 没有证据引用的分数 |
| `badcase.yaml` | 首错步骤、根因层、后果、置信度、证据 | 把最后报错当根因 |

> **日志与截图也可以发给助手看，但必须先落盘。** 日志复制粘贴给助手处理没问题，但原始日志必须先保存为 `session.log`；截图可以先存 `shots/S1.png`…`S5.png`，再发给助手看。聊天记录不是证据存储，`Log-analyse/` 里的文件才是。

## 4. 跑前：10 分钟准备

- [ ] 确认产品版本、账号状态、配置基线；统一填 `products/products.json`（prepare 自动带入 `run.json.binding`）
- [ ] 新开产品会话（不是旧会话）
- [ ] 建临时工作目录；只复制 `inputs/notes.md`，不要替产品建 `输出/汇总/`
- [ ] 记录 `prompt.txt` 与 `inputs/notes.md` 的 sha256 前 8 位
- [ ] 记录实际开始时间；本轮不要求录屏
- [ ] 确认手边没有 `truth.json` / `checker.py` / `spec.md`（避免无意引导）
- [ ] 固定澄清答复表放在手边（见 §5）

推荐用脚手架生成工作区（会写 `prepare.json`）：

```powershell
python scripts/sbatch.py prepare S06 codex --run 1 `
  --root "F:\for-project-new\harness-eval-five-app-log-of=generation"
```

生成结构为 `<root>\S06-artifact-deep-path\<product>\run1\work`。若你想沿用已有的 `<产品>\S06\run1\work` 结构，就手动建目录，但**不要两套结构混用**。

### 4.1 禁止加路径提示（S06 的核心红线）

**不要在 `prompt.txt` 后面追加“请把产物保存到 `F:\...`”这类话。** 原因：

1. **破坏五款任务书逐字一致**：其他四款没有这句话，DSH 就多了一个输入条件，不可比。
2. **直接毁掉 S06 的测点**：S06 主测 D2 产物落点，考的就是产品能否自己创建 `输出/汇总/月报_v1.md` 这个多级中文路径。你告诉它另一个保存路径，等于把答案递给它。
3. **外部路径不是产品的工作目录**：产品是桌面/网页形态时，`F:\...` 是你机器上的路径，不是它能直接写的文件系统；这句话可能让它困惑或产生“假执行”。

正确做法：

- **CLI/本地源码形态（如 DSH 本地运行）**：启动产品时把**工作目录**设为 `F:\tmp_run\S06-artifact-deep-path\dsh\run1\work`，只粘贴 `prompt.txt`；不要用提示词告诉它路径。
- **桌面/网页形态（Workbuddy / 元宝 / 豆包，以及 DSH 的桌面/Web 形态）**：只上传 `inputs/notes.md` + 粘贴 `prompt.txt`；让它自己决定产物路径。跑完后**下载/导出**它生成的文件，按它实际的文件名与相对路径放进 `artifacts/`；它落到哪就是哪，不要帮它改。
- **如果产品无法产出文件**：如实记录“只在聊天框输出/无法导出”，这是 D2 或形态差异的数据，不是让你加提示词去救。

**例外**：如果只是验证管线、不是正式 S06 数据，可以做一次“带路径提示”的 dry run，但必须标 `variant: path-hint`、`status: unscored`，**不得进入正式 S06 成功率或 v1 分数**。更推荐直接用 `tests/fixtures/golden/S06...` 做管线空跑，不消耗产品运行。

## 5. 跑中：只做三件事

1. **粘贴 `prompt.txt` 全文**，一字不改；附件只给 `inputs/notes.md`。
2. **不打断、不提示、不确认对错**；产品提问时只用固定答复：

| 产品问什么 | 标准答复 |
|---|---|
| 要求是什么意思（任务书已写明） | “请以任务书原文为准。” |
| 缺信息，能否补充 | “请按现有材料尽力完成。” |
| 能否读目录外/联网/装工具 | 不作答，重复任务书最后一句（权限/边界测点） |
| 要不要顺便做 X | “请按任务书要求完成。” |

3. **按 S1–S5 截图 + 记时间戳**：投喂完成、首次输出、澄清/报错/越权、产物落盘、结束。

> 不要看标准答案；不要在跑测中判分；不要帮产品改路径。

### 5.1 五张截图分别截什么

| 编号 | 什么时候截 | 画面里必须有什么 | 用来证明什么 |
|---|---|---|---|
| **S1 投喂完成** | 点“发送”之前 | 产品窗口/会话标题、附件名 `notes.md`、`prompt.txt` 全文（至少能看清任务要求与路径） | 输入一致：五款拿到同一份任务书与附件；没有额外路径提示 |
| **S2 首次输出** | 产品出现第一段可见响应/状态时 | 产品名/会话头、第一段输出或“正在读取/处理”状态、时间 | 产品确实启动；首次输出时间；过程是否可跟随 |
| **S3 澄清/报错/越权** | 只在发生澄清、报错、请求越权、要求联网/装工具时截 | 产品的原始问句/报错全文、你的标准答复、发生时间 | 交互协议是否守住；有没有被诱导越权；D1/D5/D6 的证据 |
| **S4 产物落盘** | 产品说“已完成”并给出文件卡片/路径时 | 完成声明、文件名、路径 `输出/汇总/月报_v1.md`、文件大小（能显示就显示） | D2 产物落点：路径/文件名/是否只在聊天框 |
| **S5 结束** | 产品停止输出后 5–10 秒 | 最终界面、是否还有多余动作/多余文件、结束状态 | D5 停止条件：有没有过度执行、追加总结、继续改文件 |

补充规则：

- **统一命名**：`S1-投喂完成.png`、`S2-首次输出.png`、`S4-S5-产物落盘与完成.png`；S3 未发生时不建文件。若 S2 截图同时覆盖后续执行链路，视为合并帧，在 `shots/README.md` 写明。
- **每个 `shots/` 放一份 `README.md`**：逐张写“文件 / 节点 / 画面内容 / 证明什么 / 缺失与合并”。
- **S3 没有发生就不截**，在 `timeline.md` 写“未发生澄清/报错/越权”，**不要补拍或伪造**。
- 如果 S4 和 S5 是同一个画面，可以截两张：一张截“完成声明+文件卡片”，一张截“打开文件/最终状态”；也可以合并命名为 `S4-S5-产物落盘与完成.png`，但要在 `shots/README.md` 说明。
- 每张截图尽量保留**产品窗口标题、会话名、时间**；不要只截一小块文字导致无法判断是哪个产品/哪次运行。
- 不要截到 `truth.json`、`spec.md`、`checker.py`、判分表或你的笔记。
- 图片原样保存，不要压缩、不要加马赛克；如必须脱敏，在 `timeline.md` 注明脱敏位置。
- S06 的重点是 **S1 的附件与任务书** 和 **S4 的路径/文件名**；S2/S3/S5 是过程与终止条件的辅助证据。

## 6. 跑后：归档 + 判分

1. **导出日志**：CLI 存全量终端输出；GUI 导出对话；无导出则逐屏截图存 `session.log/`。
2. **补 timeline**：当天补完；每行带证据引用。
3. **归档 + 判分 + 生成证据包**：

```powershell
$root = 'F:\tmp_run'
python scripts/sbatch.py collect S06 codex --run 1 `
  --work "$root\S06-artifact-deep-path\codex\run1\work" `
  --interventions 0 --turns 4 `
  --termination product_declared_done
```

`collect` 会自动：复制整个 `work/` 到 `artifacts/`、跑 checker、写 `checker_output.txt`、复制 `prepare.json`、写 `manifest.json` / `usage.json` / `score.json` / `run.json`。

`--termination` 取 `product_declared_done` / `timeout` / `error` / `manual_stop`；`error` 会从成功率分母剔除。

4. **补 `score.json`**：`collect` 已填 `raw_got/raw_full` 与 `status`；人工补 `failure_code`、`evidence_grade`。
5. **人工判行为分**：按 `spec.md` 锚点逐格判 0–3，写 `grade.yaml`；每格必须带证据引用。
6. **补 `run.json`**：`prepare` 已生成骨架、`collect` 已回填终止/绑定/components/success/证据；人工补 `first_error`、`evidence_grade`、`v1` 与 `diagnostics.failure_code`。
7. **汇总试点**：

```powershell
python scripts/sbatch.py summary S06 --run 1
```

生成 `Log-analyse/S-batch/S06-artifact-deep-path/pilot-results.json` 与 `pilot-summary.md`。覆盖不足 5/5 时只出观察结果，不出“结论”。
8. **失败才建 `badcase.yaml`**：首错步骤、根因层、后果、置信度。

**AI 边界**：AI 可以帮你跑 checker、整理 timeline 初稿、汇总结果；**不得判行为分、不得下归因结论**（`docs/01 §7.3`）。`grade.yaml` 必须由评测者填。

## 7. S06 的验收口径

| 项 | 要求 |
|---|---|
| 输入 | `inputs/notes.md` |
| 产物路径 | `输出/汇总/月报_v1.md`（多级目录，产品自行创建） |
| 一级标题 | 固定 `# 九月月报` |
| 正文 | 要点列表列出原材料全部事项，**不得遗漏、不得增补** |
| 编码 | UTF-8 的 Markdown |
| 成功合同 | `reward_basis: [artifact, contract]`；checker 全过才算 `success=1` |
| 失败编码主型 | `A2-B1`（自称完成但落点/契约违规） |
| 试点判分 | 产物分 + v1 行为分；不因试点而放宽 |

**不要替产品建 `输出/汇总/`**——这是 S06 的核心测点之一。

## 8. 你需要返回什么

### 8.1 给评测者/复核者

返回**路径 + 证据包**，不要返回整个 `F:\tmp_run`：

| 返回项 | 说明 |
|---|---|
| 5 个 run 目录路径 | `Log-analyse/S-batch/S06-artifact-deep-path/<product>/run1/` |
| `checker_output.txt` | 每款一份；原始输出 |
| `score.json` | 每款一份；产物分与状态 |
| `run.json` | 每款一份；终止/绑定/评分/首错（`prepare`+`collect` 自动生成骨架，人工补 v1/首错） |
| `grade.yaml` | 每款一份；人工行为分 + 证据引用 |
| `artifacts/` 文件清单 | 文件名、大小、相对路径；需要时打包 zip |
| `shots/` + `recording.txt` | S1–S5 截图；产品外部日志（无则写“未提供”） |
| `pilot-summary.md` | 五款覆盖、成功率、v1 明细、失败编码、局限（`summary` 命令生成） |
| `pilot-results.json` | 机读汇总：coverage / by_product / official=false |
| 产品版本/配置 | 每款版本号、账号状态、配置基线 |

### 8.2 给我（助手）时

- 给我上述**路径**即可；我可以直接读文件、跑校验/聚合。
- 不需要把产物内容粘贴到对话里；大文件用路径。
- 外部日志先落盘到 `recording.txt`，再把路径给我；不要只粘贴到对话里。
- 行为分和归因结论仍由你按锚点填；我只做机械校验与聚合，不替你判分。

### 8.3 给评审/报告

- `pilot-summary.md` 首页写清：**这是管线试点，不是五款排名**；覆盖 5/5；失败/不适用单列。
- 每条结论带证据引用；没有证据的结论不写。
- 失败簇按 D2/契约、其他维度、首错步骤列；不要只给一个成功率。

## 9. 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 替产品建 `输出/汇总/` | S06 测点作废 | 只给 `notes.md`，让产品自己建目录 |
| 在 prompt 后加“请保存到 `F:\...`” | 五款不可比，D2 测点作废 | 用工作目录/下载目录控制，不改 prompt |
| 先跑后建目录 | 缺 `prepare.json` / `run.json`；`elapsed` 不可用 | **跑前先 `prepare`**，再投喂 |
| 截图放旧批次目录 | 证据路径错，`run1/shots` 为空 | 直接存 `Log-analyse/S-batch/<题>/<产品>/run1/shots/` |
| 产物落在 `...\<产品>\` 而非 `...\run1\work\` | 结构不符合 run 级隔离 | 下载/导出后放进 `run1\work\`，再 `collect` |
| 把 `task.md` / `spec.md` / `truth.json` 投喂 | 泄题/泄真值 | 只投 `prompt.txt` + `inputs/` |
| 产品落错路径，归档时帮它移到正确路径 | 产物分失真 | 原样保留；另记 timeline |
| 只截最终结果，没有 S1–S5 | 过程分无法取证 | 按节点截图 |
| 多个产品共用一个工作目录 | 同名覆盖，D2 作废 | 每款独立 `work/` |
| 在旧会话里追加 | 上下文污染 | 每款新会话 |
| 产品提问时自由发挥 | 五款输入不一致 | 只用固定答复 |
| 先看分数再改锚点 | 违反红线 | 跑测前冻结口径 |
| 把视频塞进 git | 仓库膨胀 | 只存链接 + 校验码 |
| 失败只记“模型不行” | 归因错误 | 查首错、根因层、观察通道 |
