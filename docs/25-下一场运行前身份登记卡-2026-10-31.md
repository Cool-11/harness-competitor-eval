# 下一场运行前身份登记卡（2026-10-31）

本卡用于未来**新场次**；不追认 S11 run1/run2，不要求现在启动 run3。裁判通道负责执行 `prepare`，评测者负责从产品界面核实实际执行态。每款、每次 run 单独建槽，绝不复用旧 `run<n>`。

| 字段 | 谁记录 | 现状/需要提供什么 |
|---|---|---|
| 唯一 `run_id`、`started_at` | `sbatch.py prepare` 自动生成 | 不必人工编 ID；发送题目前把控制台输出和 `prepare.json` 留存 |
| 题目版本、prompt/输入哈希 | `prepare` 从仓库冻结题包自动计算 | 评测者只确认实际上传/附加的是新 `work` 内那两份输入，不是别处同名文件 |
| 产品版本、账号、配置 revision | `prepare` 从 `products/products.json` 读取 | 注册表/CLI 登记截至 2026-10-23；新场前用产品“关于/设置”页核对实际版本、账号类型与配置，有变化就先更新登记 |
| 实际模型与推理强度 | 评测者看现场界面，裁判填 `--model` / `--variant` | 每场发送前确认；不可见填 `unknown`，不猜测 |
| 工具与权限 | 评测者看工具、沙箱/文件访问设置，裁判填 `--tools` / `--permissions` | 记录本场真正可用工具与权限；不要沿用上场口径 |
| Skills、Memory | 评测者核对设置并拍照，裁判填状态 | Codex 正式准入要求两者 `disabled`；其他产品如不可见则 `unknown` |
| 接口预检与真实 cwd | 评测者在本产品的独立小文件预检，裁判填 `--interface-precheck` | 换工作根必须重做；尤其 DSH 要从原生会话头/工具记录核对真实 cwd |

执行顺序：①更新产品登记并做接口预检；②在**发送题目前**由裁判运行 `python scripts/sbatch.py prepare <题号> <产品> --run <新序号> --root <已预检的根> --variant <固定配置> --model <实测或unknown> --tools <实测> --permissions <实测> --skills-state <状态> --memory-state <状态> --interface-precheck passed`；③打开同级 `prepare.json` 核对 run_id、时间、输入指纹与工作目录；④新空白会话只投喂 `prompt.txt` 和该 `work` 中的输入，留发送前 S1；⑤结束后回收现场、`collect` 和独立终裁。

`prepare.json` 是**运行前登记**，不是分数。其 `inputs_sha8` 是 SHA-256 的前 8 位，用于快速辨认输入版本；若要严格证明同字节，另保存完整 SHA-256。哈希匹配说明文件字节一致，不说明产品行为一致。原始配置修复后哈希变化正常，应同时保留修前、修后文件指纹。
