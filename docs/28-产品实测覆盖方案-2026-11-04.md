# 产品实测覆盖方案（2026-11-04）

> **历史方案提示（2026-11-06）**：本文的研究动机继续有效，但新建 `hev-v3` 运行的分轨、归因合同和证据要求以 [评测执行架构 v3](30-评测执行架构-v3-2026-11-06.md) 为准。桌面运行改用日志/会话导出证据链，录屏为可选补强。

## 为什么要做实测覆盖

题包测试证明“设计了什么刺激”，checker 回归证明“部分判卷规则能识别预设正反例”。产品实测覆盖证明的是另一件事：**在真实产品界面和当前配置下，任务、输入、工具行为、产物与裁判结论能否连成可复核的一条运行链。** 少了这一层，无法判断题目是否真有区分力、产品是否真的完成，也无法发现 S11 旧 cwd 这类产物满分却执行错位的情况。

覆盖至少分四层，不互相代替：

1. **设计覆盖**：题是否触发预定失败机制。分母是题型或机制。
2. **运行覆盖**：哪个题 × 哪款产品实际独立运行。分母是预注册的格，作废场保留但不算有效格。
3. **证据覆盖**：运行前身份、输入、过程、产物、终裁各有多少项可观察。分母是每格所需的证据项；未知保留。
4. **推断覆盖**：观察能否跨独立重复成立，以及能否通过控制模型/工具/权限归因于 Harness。n=1 只能说明当前配置下的一次观察。

因此“五款都得到 7/7”只涉及已收产物的判卷；正式结论还要证明产物来自同一次、同一输入的产品运行，并明确不可见的过程。

## 本轮最小问题与样本

第一轨选 S06 深路径交付，五款各开一场新会话，目标 5 个产品格。它检验附件读取、目录创建、文件落盘、完整性和回传。第二轨选 S11 损坏恢复；DSH run4 已有单场正式记录，其余四款先做工作区/导出能力预检，能验证哪些步骤就报告哪些步骤。两轨都不形成跨模型 Harness 排名。

先把五款 S06 做完，再决定 S11 哪些款适合做“原文件就地修复”比较。遇到一条会改变判断的差异，才冻结复测条件做独立重复；重复场与原场按 run_id 关联，不覆盖旧场。

## 每场固定取证

| 阶段 | 必留内容 | 它能证明什么 |
|---|---|---|
| 运行前 | `prepare.json`、新会话与设置截图、发送前附件/工作区截图、输入哈希 | 题面、配置、投喂对象与唯一身份 |
| 运行中 | DSH 原生日志，或桌面端从发送前到完成的连续录屏 | 原生工具调用或画面可见步骤；录屏不能证明未显示的内部读写 |
| 运行后 | 原工作区/产品导出原件、导出过程截图、产物哈希、checker 输出 | 文件来源、当前产物是否满足契约 |
| 终裁 | 行为格逐项证据、未知原因、人工复核人与日期、准入结果 | 分数及其适用范围 |

产品只能从应用内导出文件时，`prepare` 的 `work` 是**输入与收件区**，不能写成产品实际 cwd。导出文件拷入收件区时保留原件、导出动作录像/截图和哈希；`collect` 的路径匹配只证明归档槽位一致，不能独立证明产品内部工作目录。元宝无法选工作区时，S11 的“指定目录就地修复”按其真实产品形态单列。

## 逐款取证路径

| 产品 | 首选过程证据 | 特别核查 |
|---|---|---|
| DSH | 原生会话轨迹 + 发送前截图 | `session.cwd`、相对路径读写与 run 工作区一致 |
| Codex 桌面端 | 连续录屏 + 发送前工作区/附件截图 | 新会话、Memory/Skills 状态、实际产物与导出链 |
| WorkBuddy | 连续录屏 + 导出过程 | 附件来源、产物是否为原工作区文件或副本 |
| 豆包办公 | 连续录屏 + 导出过程 | 是否引用仓库题包路径；输出来源与收件文件一致 |
| 元宝专家模式 | 连续录屏 + 应用内文件卡片导出 | 内部沙箱与导出来源；不能把本地收件区称为实际 cwd |

## 准入与报告

`collect` 的 `native_trace` 或 `screen_recording` 模式只检查必需证据文件存在、路径和哈希，并记录证据类型。人工终裁仍须核对画面/日志与 run_id、输入、产物是否对应。无证据、混用旧工作区、人工补造输入的场次记 unknown 或 invalid；真实失败且证据完整的场次记 fail 并纳入有效运行。

每周只报同一截止时间的四个数：新增独立场、有效场、正式准入场、正式覆盖格。另报 invalid 和 unknown 的原因。正式表旁注明：题、产品、配置、证据模式、n、可见维度、不可见维度。不要把“5 款 × 2 题 = 10 格”写成 10 次已完成实验。

完成本轮的验收物是一张 5 行 S06 索引表和一张按产品形态分轨的 S11 表；评审者应能从任一行点回发送前证据、全程记录、原始产物、判卷和终裁。
