# v3 桌面产品手工运行卡（2026-11-06）

适用于 WorkBuddy、豆包、元宝的新场。三款都进入 `B_native_product + product_result + desktop_export`：评测当前产品整体交付，不把差异归因到 Harness。

## 每场步骤

1. 核对新 run 槽不存在，记录实际产品版本、模型/模式、工具权限、Memory/Skills 可见状态；未知就填 `unknown`。
2. 先 `prepare`，只把 `prompt.txt` 正文和 `inputs/` 文件交给新会话。不得暴露 `task.md`、`spec.md`、`truth.json`、`checker.py` 或历史结果。
3. 发送前保存截图；完成后保存最终状态截图。导出原始会话/日志，并另存一份能说明“从哪个产品、哪个会话、以何方式导出到何处”的来源证据。
4. 保留产品导出的原始文件。若要复制到 `work` 收件区，保留导出原件和来源证据，不把收件区写成产品内部 cwd。
5. `collect` 后人工复核，再 `adjudicate`。真实失败记 `fail`，证据不足记 `unknown`，工作区或输入错位记 `invalid`。

## 命令模板

```powershell
.\.venv\Scripts\python.exe scripts\sbatch.py prepare S06 workbuddy `
  --run <新编号> --root C:\tmp_run `
  --protocol-version hev-v3 `
  --comparison-track B_native_product `
  --admission-track product_result `
  --surface desktop `
  --product-version "<实际版本>" `
  --model "<实际模型或unknown>" `
  --provider "<实际服务方或unknown>" `
  --reasoning "<实际档位或unknown>" `
  --sampling "<实际参数或unknown>" `
  --network "<实际策略或unknown>" `
  --tools "<可见工具，逗号分隔>" `
  --permissions "<实际权限>" `
  --skills-state <enabled|disabled|unknown|not_applicable> `
  --memory-state <enabled|disabled|unknown|not_applicable> `
  --interface-precheck passed
```

完成运行并将原始产物放入该场 `work` 后：

```powershell
.\.venv\Scripts\python.exe scripts\sbatch.py collect S06 workbuddy `
  --run <同一编号> `
  --work "<prepare.json 中的 work_dir>" `
  --evidence-mode desktop_export `
  --preflight-shot "<发送前截图>" `
  --completion-shot "<完成截图>" `
  --session-export "<原始会话或日志导出>" `
  --export-evidence "<导出来源与落点证据>"
```

把产品名替换为 `doubao` 或 `yuanbao`。如确有必要可以额外录屏，但 `desktop_export` 不要求 `--recording`。

人工复核后：

```powershell
.\.venv\Scripts\python.exe scripts\sbatch.py adjudicate S06 workbuddy `
  --run <同一编号> --evidence-grade C --final-ruling <pass|fail|unknown|invalid> `
  --rules-frozen yes --task-valid yes --evidence-valid yes --uncontaminated yes `
  --adjudicator "<复核人>" --notes "<证据边界与异常>"
```

若终裁为 `unknown` 或 `invalid`，按事实填写 `evidence-valid`、`uncontaminated`，不要为了准入统一写 `yes`。

## 最小证据目录

```text
run<n>-evidence/
  preflight.png
  completion.png
  session-export.<原始格式>
  export-source.png 或 export-source.json
  original-artifacts/
```

录屏可放在同目录作为补强材料。任何派生转码、整理版日志或重命名产物都不能替代原件。
