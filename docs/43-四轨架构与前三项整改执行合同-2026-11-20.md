## 版本与运行绑定

题包沿用 `tasks/`、`task_revision` 和 `evaluator_revision`；配置沿用产品版本、配置证据和 SHA-256；实验沿用 runner 计划及控制合同；运行沿用先 prepare 再 collect/adjudicate 的唯一身份。恢复复用基线配置身份及其 SHA-256，但必须使用新 run 和工作区。

`resolve` 现在冻结题面、初始输入、checker/spec/truth、配置证据、命令行 `--patch` 文件及机制预注册原件。再次解析、预检、每场 prepare 前、启动前与收件前均检查当前依赖。新增输入、源计划被改、补丁或配置变化都会拒绝继续。运行中发现漂移时保存本场工作区、原始 stdout/stderr、原生轨迹入口及 `freeze-error.json`，停止余下槽位，不用新 checker 对旧条件下的产物判分。旧解析计划缺清单则拒绝启动，不向历史文件补字段。

这只覆盖明确列入依赖的文件，不声称已冻结服务端模型权重、home-level 配置、操作系统和全部依赖包。它们仍需实际环境镜像或可核验配置合同；单填环境名称不足以通过科学上的因果审核。

## P2 单变量合同与实际生效

`M_mechanism.control_contract` 要求：`experiment_id`、`component=tool-pwsh`、`arm=C0/C1/C0-restored`、模型/provider/reasoning/sampling、环境/网络/权限、Skills/Memory、基线/干预配置身份及各自 `configuration_sha256`、预注册路径、invalid/stop/analyse 规则、主要终点及预算。其中代码字段为 `invalid_rule`、`stop_rule`、`analysis_plan`；主要终点当前固定 `task_success`。

`baseline_tools` 与 `intervention_tools` 必须仅差 C1 去掉 `pwsh`，保留其他工具。恢复臂读取 C0 的工具集和配置哈希；配置快照必须与当前臂绑定。标准 headless 启动，不允许自定义 command，也不允许同时加入 delivery_gate。运行后从所有原生请求核验模型、provider、reasoning、sampling、权限和工具列表；未生效或不一致保留证据、按 `unverified` 收件并停止，不进入正式比较。

`effective` 仅表示本脚本检查的模型/权限/工具条件符合声明，不代表工具路径被实际触发，不代表全配置唯一差异已经独立审核，更不代表任务成功或因果成立。原生工具列表不含 pwsh 可以证明工具移除；只看到任务未调用 pwsh，不能证明工具被移除。触发率、恢复路径与交付结果仍须独立记录。

当前 `budget.max_runs`、`timeout_seconds`、`max_tokens`、`max_cost` 均要求有限正值，前三项为整数。runner 会限制批次槽位数和单场超时；token、金额是待外部计量/强制执行的合同上限，当前没有自动熔断能力。金额单位和跨批次总上限必须在预注册中明确。**在计量和隔离未解决前，此接入不能作为允许付费机制跑测的依据。** 本轮不提供虚构预算的可发射正式计划，不向旧 P2 实验追填新合同。

## 读取隔离与当前停止原因

本轮给本地 DSH 子进程启动器增加不调用模型的 OS 读取拒绝探测：同 OS 身份的子进程尝试读 `AGENTS.md` 和本批题目的 checker/spec/truth，仅返回路径和 readable/denied/unknown，不返回内容。任一路径可读、丢失或探测异常均不能通过。该检查用于阻止已知 r13 泄露形态；拒绝发生在 prepare 之前。

当前机器实测结果为 **readable，预检拒绝**。本地同用户直接启动 DSH、只改 cwd 或 `workspace-write` 都不能解决该问题。runner 尚未实现容器/其他身份的远程启动与安全收件；不得伪造一份“passed” JSON 绕过。后续应提供裁判材料不可访问的容器/VM/账号执行环境，再实现相应启动与取证适配。这项负向探测只是必要检查，通过也不能单独证明所有敏感路径和历史文件已隔离。

## 判卷、复评与重新评分

完成度、过程分、安全闸门沿用冻结合同。新版 S06/S11 校准包保存 fixture、题面、输入和 checker/spec/truth 的精确指纹；无依据增补、堆词、遗漏、等价改写均可复算。机械满分与完整语义通过分别报告；S06/S11 fixture 仍待真实人工签署。禁止按临时反例直接改历史分数。

`reviewer_agreement.py` 接收原评分 CSV、独立复评 CSV、冻结协议和可选关系声明。要求保留所有固定格位，拒绝重复、删格、非法档位、缺证据/理由；空白为 pending、弃权另计，未填完不发布有选择的局部一致率。完成后输出有效分母、exact agreement、相差一档比例、四档 quadratic weighted κ、逐维结果和分歧原句。档位退化时 κ 为 null。工具保存声明，但不能认证评审者身份与独立性，仲裁也须另存，不覆盖两份原判。

本轮对既有五场 20 格只提取原判，独立复评仍空，结果是 pending/20、所有一致性指标 null。协调者原判文件不得提前提供复核人。K4 的历史签署不替代本轮独立复评。评分算法参考 [scikit-learn 官方 Cohen κ 定义](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.cohen_kappa_score.html)。

项目审核的 58/100 是完整研究成果口径的历史评分；本轮按条款重新核验工程完成状态，不伪装为审核者重新给分。没有新组件因果结果、独立复评和未见验收，不能因软件测试增加就宣称项目达到 70/100 或以上。产品历史得分也不因工程整改自动上调。

## 统计规范的实现和适用范围

`evaluation_stats.wilson` 对有效独立二项观察给出 Wilson 区间，n=0 返回 null，不接收未知伪造的 0。7/10 的 95% 区间约 39.7%–89.2%，这是公式校验，不是本项目已做完 10 例验收。公式参照 [NIST](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。便利样本的区间不能宣称覆盖所有 BadCase。

`paired_task_effect` 只接收明确配对 ID 的 C0/C1 有效二元终裁，先算每题配对差值均值，再对任务簇重采样，保持配对并给予每题相同权重。固定 seed、draws、95% percentile 索引约定；少于三个任务簇不输出区间，即使多于此数量仍是可能不稳健的描述性估计，不自动证明因果或等效。输入不能丢弃 unknown/invalid 后不报告；这些分母由外部冻结分析协议另列。本轮未将现有五产品混合配置或 P2 每臂一次的历史数据塞入此函数计算效应。

## 后续跑测步骤与验收

1. 在裁判环境完成 oracle、正例/近错例/反向对照和语义人工签署，明确两个机制触发任务与一题负对照。改题须新版本。
2. 取得隔离执行环境，冻结 DSH 版本、完整解析配置、工具、模型、Skills/Memory、环境和计量方式；验证拒读及实际唯一差异。
3. 明确总预算、重复数和顺序，冻结前瞻实验计划及 C0/C1/恢复配置；不沿用旧 run 序号，不预填结果。
4. `validate → resolve → preflight`；任何漂移/隔离失败均停止。正式调用必须使用可安全执行的适配器，当前同用户本地 DSH 被阻止。
5. `prepare → 独立新会话执行 → collect → checker → 人工语义/行为复核 → adjudicate`；保留原始日志、hash、触发证据、用量和所有失败尝试。
6. 按冻结分母分析原故障、总结果、成本、回归和恢复；触发未知不得解释为组件无效。没有效果反转也如实报告，不追加调用等显著。
7. 机制成立后才选择真正触发同机制的 Terminal-Bench 任务做迁移，分开原生和文件变体；最后另冻 10 个未见案例验收，原始参考根因由独立来源持有并最终揭盲。

当前可验收的是工程行为：拒绝读取暴露、拒绝源漂移、识别运行时干预未生效、保留原件、分轨派生、拒绝重复报告覆盖和可重算的评分统计。研究验收尚欠：真实可隔离发射、两个触发任务和负对照、足够独立重复、组件结果反转、人工签署/独立复评、外部迁移和未见验收。两者分别交付，不互相冒充。
