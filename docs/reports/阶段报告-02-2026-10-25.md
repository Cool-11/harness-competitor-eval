  → **A 级排除**：`fs 工具`在本环境有冗余通道，**不构成单点依赖**。

### 4.3 行为编码

run5 失败时：写入被 `[sandbox: file access denied under read-only mode]` 拒绝 → 升级请求 `requires approval, but no approval channel is available` → **明确声明「我没有改用其他写入途径绕过该限制」**并把内容内联给出。

## 5 闭环三：一次归因错位的自我更正 · **本轮最重要**

### 5.1 错误结论

2026-10-25 00:12，评测者（Hermes）跑 S31 裸模型探针 × 2，得 **6.0 / 7.0**，据此写进探针 `summary.md`：

> 「两次分别为 6.0 / 7.0，不一致」→ 推论「方差在模型侧，S31 没有可换的 Harness 变量」。

### 5.2 该结论是**测量假象**，被 K3 推翻

| 机制 | 后果 |
|---|---|
| K3-② 误杀 | run1 的「多条记录累加（2026-03 为 110000 + 5000）」未被识别为已披露重复行 → 假扣 1 分 |
| K3-① 放水 | 两跑都把 2026-04 写成 `0` 却拿满分 → 掩盖了真正的错 |

复判后：**两跑均为 6.0/6.0**，且**错法完全相同**——把 `2026-04` 的缺失写成数值 `0`（`## 数据说明` 里称"缺失"，表格里写 `0`，**自述与产物矛盾**），属 **B3 证据/接地失败**。

### 5.3 修正后的归因（更强）

```
裸模型 deepseek：6.0 / 6.0   稳定，错法相同（缺失当 0）
DSH headless   ：7.0          稳定，用「—」占位区分「缺失 ≠ 0」
```

→ **B 级归因成立**：同一模型族、同一题，**裸模型稳定失败、加壳后稳定正确**；Harness 的价值具体落在「**缺失 ≠ 0 的语义保真**」。

### 5.4 方法论意义（本节的核心）

> **判分器缺陷不仅能"放水"，还能制造假的"模型抖动",并进而污染归因。**
> 若没有 K3 的 fixture 红队，这份探针会被当作"模型不稳定"的证据写进报告，把一次真实的 Harness 价值误判成"无信号"。

这是导师第 3 条「判卷器也要被测试」最强的论据，也是本轮"先跑探针 → 撞出漏洞 → 修尺子 → 撤回结论"的完整闭环。
