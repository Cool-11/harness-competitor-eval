## 一、本周进展

1. **S11 五款复评收件**：整理 S1/S2/S4/S5、两份输出和设置基线。核对原始 `config.json`、`data.csv` 的哈希及正确筛选结果 A1/A3/A5。收件侧缺少完整输入与修复后配置，因此只能确认“已回收产物符合 checker”，不能确认每款原文件就地修复。DSH 会话日志进一步证实真实 cwd 落在旧 S06/run1/work，产物从旧目录复制入 S11 收件箱；该场不满足无污染准入。
2. **修订 S11 判卷器 K4**：历史元宝 S11 run1 的报告只明确指出一处损坏，旧 checker 把“末尾补上逗号”的修复动作误认成第二处缺陷，形成假阳性。修后自动复算由 **7/7 降为 6/7**，其余四款历史产物仍为 7/7；修前后代码、正例、近错例、反向对照和回归输出已保留。独立人工签署仍待完成，因此 6/7 只作为自动回归结果，不作为已签署的对外分数。[K4 执行卡](../23-本周闭环执行卡-S11-K4-2026-10-30.md) · [签署页](../../tests/regression/checker-revisions/S11-K4/SIGNOFF.md)。
3. **建立运行身份与准入账**：`sbatch.py` 的运行前 `prepare`、证据收集及准入字段已扩充，历史运行与新制式正式表分开；[准入规范](../22-运行身份与正式准入规范-v1.md) 和 [六类账](../../Log-analyse/evaluation-ledger.md) 记录了边界。S11 run2 没有运行前 `prepare.json`，事后索引只用来定位证据，不补造 run_id。
4. **AutoRubric 发现性试验**：从已签署的 S06/S11 历史场次按完整 run 分组，导出 **10 场、40 个行为格**；分成 **24 个 dev 格、16 个 holdout 格**。已形成 [候选 rubric v2](../../experiments/autorubric/pilot-2026-10-30/rubric-v2-candidate.yaml)：加入证据不足时 abstain、将 S11 恢复结果与损坏定位分开、避免产物分和行为分重复计分。候选由人工据现有失败模式整理，**尚未执行独立模型生成与 holdout 盲评**，不能宣称 AutoRubric 已提升一致性，也不改正式规则。[实验说明](../../experiments/autorubric/pilot-2026-10-30/README.md)。

## 二、本周难点与判断

- **产物满分不等于可靠比较**：五款 7/7 容易被读成同一水平；逐项查看运行身份、截图时间点与工具轨迹后，发现准入缺口和 DSH 跨题落盘。结论收窄为单题产物事实，行为分保留未知。
- **判卷器可能制造假阳性**：K4 的“修复动作被算成缺陷描述”说明词面规则需要近错例和反向对照。自动回归已修复该样本，独立验收仍是发布修订分的前置步骤。
- **AutoRubric 先改锚点，再测效果**：把模糊档位改成可观察行为，并设置 abstain；样本仅两道题且 holdout 未盲评，现阶段只得到候选规则，尚无泛化结论。
