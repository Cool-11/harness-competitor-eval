# DSH 下一轮机制实验：发射前可行性核查（2026-11-21）

> 后续进展：本页是新假设形成前的停发快照。随后另立 [S06 外部交付核查预注册](s06-gate-preregistration.md)，采用新 ¥2 预算代理并执行一场 C0；[结果](results.md)为机械 7/7，C1 与恢复臂按停止线未发射。下文“零调用”只对应本页最初核查时点。

用户授权模型 DeepSeek V4.1 Flash、费用总上限 ¥2、时长总上限 120 秒。官方[模型与价格页](https://api-docs.deepseek.com/quick_start/pricing/)当前将 API 名称 `deepseek-flash` 指向 DeepSeek-V4.1-Flash-1017；这是模型服务路由说明，实际每场仍须从原生请求核验。

**结论：本轮没有发射产品运行，也没有预占 run_id 或调用模型。** 现有 S11 隔离 Linux 基线 run16 已 7/7，追加 run17 的外部交付检查未触发，不能作为“失败→修复→恢复”的触发基线。旧 Windows P2 三臂对交付均失败，重复同一补丁不能提供新假设；P8 遥测和 P7 停止事件的旧绑定已失效；只读拒写可能符合权限合同。当前没有经核验的另一独立决策接缝及在相同隔离环境中可触发的失败任务，故付费发射会使 120 秒和 ¥2 预算只买到不可解释的观察。

现有 `p0_budget_proxy*.mjs` 是历史实验的冻结源，硬编码累计 ¥5、旧人民币预留费率及接近 600 秒的上游超时。不得直接用它们执行新授权，也不应修改历史源来回填旧实验。下一次发射前另建版本，按当日官方价格与保守汇率在转发前预留，分别设置 **¥2 累计熔断、120 秒总墙钟熔断**；预注册唯一组件、预期触发、A/B/A 恢复、无效场与停止线，再冻结源哈希。若这些条件不满足，继续保持零调用。
