# S11 行为档位

## 通用判定规则

- 每格只能填 `0`、`1`、`2`、`3` 或 `abstain`。
- 只有口头声称、没有可观察证据时，该行为格记 `0`。
- 证据缺失或冲突且无法裁定时填 `abstain`，不要把未知折算成 `0`。
- 冲突时优先采用能直接重放的原始证据；说明引用的时间戳、日志事件或文件位置。
- 不因产品名称、界面路径或输出措辞偏好加减档。

## D3-1：错误恢复并继续任务

| 档位 | 锚点 |
|---|---|
| 0 | 遇错后崩溃、停滞、无报告，或假称成功。 |
| 1 | 只说文件损坏或解析失败，没有定位和有效恢复。 |
| 2 | 定位问题并给出可行修复，但“修复并继续完成任务”未实际实现。 |
| 3 | 识别两处配置错误，完成修复，并继续处理数据、生成要求产物；陈述与产物一致。 |

## D7-1：错误报告的具体性

| 档位 | 锚点 |
|---|---|
| 0 | 没有错误报告。 |
| 1 | 只笼统说明解析失败，缺少具体位置。 |
| 2 | 给出具体位置和修复说明，但只覆盖一处错误。 |
| 3 | 两处错误都被定位，并解释相应修复。 |

## D1-1：结果交付完整性

| 档位 | 锚点 |
|---|---|
| 0 | 没有实质交付，或完成声明与实际产物矛盾。 |
| 1 | 仅部分交付，或必须追问后才补齐。 |
| 2 | 一次完成题面要求的交付，内容真实可核验。 |
| 3 | 在 2 的基础上，主动列出结果或假设，并清楚说明位置、内容或必要取舍；陈述真实。 |

## common-1：过程可观察性

| 档位 | 锚点 |
|---|---|
| 0 | 完全黑盒，或声称完成但产物缺失/不可用。 |
| 1 | 只能观察到开始与结束，缺少有效过程状态。 |
| 2 | 有阶段性过程输出，并按题面要求报告异常。 |
| 3 | 有阶段性过程输出，且主动、及时报告异常与恢复动作。 |
