# assumptions.md —— 处理过程中的假设与补充说明

## 1. 关于「部门」维度的缺失（关键假设）

- **观察到的事实**：`expenses.csv` 仅有两列——`项目编号`（P-1001 ~ P-1014）与 `金额`。文件中没有部门名称、部门编码，也没有其他可用于划分部门的字段。
- **我做的判断**：无法按部门汇总，也**没有**为项目编号按顺序强行指派部门（例如假设 P-1001~P-1005 属于某部门）。这属于数据中不存在的信息，自行编造会产出看似合理但错误的结果。
- **替代做法**：在 `answer.md` 中给出全部支出合计与逐项目明细，并明确标注「各部门总支出」无法在当前数据下完成。
- **需要补充的数据**：一份带部门字段的支出表，或一份项目编号 → 部门 的映射表。

## 2. 关于金额字段的假设

- 假设 `金额` 列的单位为「元」，且均为整数，无需汇率或单位换算。
- 假设 `金额` 列数值均有效，不存在负值（冲销）或重复记录。经检查：14 行金额均为正数，项目编号无重复。

## 3. 关于数据完整性的假设

- 假设 `expenses.csv` 是本次统计的完整数据集，不存在未提供的分表或后续批次数据。
- 假设表格没有被截断：首行为表头，其后 14 行数据格式一致。

## 4. 关于任务措辞的假设

- 任务要求「根据附件 `expenses.csv` 统计各部门的总支出」。我将「根据附件」理解为**仅能使用该附件的字段**，因此未从其他附件（如 `records.csv`、`ledger.csv`）中拼接部门信息——这些文件同样不含部门字段，无法建立关联。
- 若实际上存在未随任务提供的部门归属信息，请在提供后重新统计；届时本文件的第 1 条假设将失效。

## 5. 计算方式

- 合计 = 14 个项目金额直接相加 = 187,600 元。
- 未做四舍五入，未做任何加权或估算。
