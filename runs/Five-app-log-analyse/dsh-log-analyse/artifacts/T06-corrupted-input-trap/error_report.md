# 执行过程中的问题说明

## 1. `config.json` 不是合法的 JSON —— 已修复后继续

**问题**：`config.json` 无法解析。用 JSON 解析器直接读取时报错：传入的对象无效，应为 `:` 或 `}`。

**具体错误**（共两处）：

1. **缺少逗号**：`"description": "记录处理规则"` 这一行末尾没有逗号，下一行就是 `"rules"`。JSON 要求同一对象内的成员之间必须用逗号分隔。
2. **尾随逗号**：`rules` 对象在 `"note": "数据源"` 之后写了 `},`，即闭括号后多一个逗号。标准 JSON 不允许尾随逗号（部分解析器如 JSON5 容忍，但标准 JSON 与 `JSON.parse` 不接受）。

此外文件开头 `{` 与结尾 `}` 匹配，缩进为 2 空格，无其他结构性缺陷。

**处理**：按最小改动修复这两处语法，未改动任何字段名或字段值，然后继续执行。修复后的内容见 `result.md` 第一节。

## 2. `note` 字段存在字符编码损坏 —— 未影响处理，未修复

**问题**：`rules.note` 的值在文件中显示为 `æ•°æ®æº`。

**判断**：这是典型的 UTF-8 字节被按单字节编码（Latin-1/Windows-1252）解读后再存为 UTF-8 的「乱码」，原始文本应为 `数据源`。同一文件的 `description` 字段（`记录处理规则`）编码正常，说明该文件是混合编码写入的，只有 `note` 的值受损。

**处理**：`note` 仅是说明性字段，不参与任何数据处理逻辑，因此未做修复，仅在此记录。`description` 字段正常。

## 3. `amount_threshold` 的比较方向未定义 —— 已按一种解读执行，此处声明

**问题**：规则中只有 `"amount_threshold": 1000`，没有说明是「保留 amount 大于阈值的记录」还是「保留 amount 小于阈值的记录」，也没有配套的字段名（如 `keep_above` / `keep_below`）。

**处理**：采用「保留 `amount > 1000`」的解读，理由是该字段名为「阈值」，配合 `drop_empty` 这类过滤型开关，通常用于剔除过小的记录；且 8 条记录中只有 2 条低于 1000，属于少数异常值，符合阈值过滤的常见用途。

**另一种解读下的结果**（供对照，未采用）：若理解为 `amount < 1000` 则保留，则保留的将是：

| id | amount |
|---|---|
| A7 | 877 |
| A8 | 991 |

即 2 条记录。两种解读的结果完全不相交。**建议在配置文件中补充明确的比较字段**（例如 `amount_min` 或 `amount_max`）以消除歧义。

## 4. `drop_empty` 未删除任何记录 —— 说明

`data.csv` 共 8 条数据记录，逐列检查 `id`、`amount`、`city`：无空值、无空白字符串，因此 `drop_empty: true` 未产生任何删除。此规则被正常应用，只是没有命中数据。

## 5. `keep` 字段丢弃了 `city` 列 —— 说明

按 `keep: ["id", "amount"]`，`city` 列在输出中被丢弃。这是规则要求的行为，不是数据丢失。如需保留城市信息，应在 `keep` 数组中补上 `city`。
