## 零点、五款统一规则：跨会话记忆一律关闭（对 `docs/01 §1` 的细化，待作者确认）

`§1` 规定"产品自带记忆/个性化保持默认；若其内容可能影响任务执行，可关闭并记录"。落地时需要**五款一致**的口径，否则它本身就成了变量：

| 功能 | 统一处置 | 理由 |
|---|---|---|
| **跨会话/长期记忆** | **统一关闭 + 截图留痕** | `§6.0` 要求每题新开会话；长期记忆会把历史偏好注入新会话，直接破坏会话独立性 |
| 产品自带个性化（语气/称呼等） | 保持默认，记录内容 | 不影响任务执行的不必动 |
| 个人加装技能/插件/自定义指令 | 统一停用 + 留痕 + 评测后恢复 | `§1` 明确要求 |
| 底层模型与默认参数 | 保持产品默认；**若被第三方工具改过则必须恢复默认** | 见 Codex 一节 |

## 二点五、附：Codex 专项处置（**没有订阅账号**怎么办）

你的情况：Codex 装了、但**没有 ChatGPT 订阅**（所以 ccswitch 才把它指到了 DeepSeek 的 API）。

### 结论：走**路线 B**，而且这件事可以变成加分项

**做法**
1. **保留** ccswitch 的 `custom` provider（DeepSeek 后端）——没有订阅就没有官方模型可用，硬切官方档只会让 Codex 不可用
2. **但必须删掉这些参数行**（恢复 Codex 默认）：
   ```
   model_reasoning_effort = "max"
   model_context_window = 1000000
   model_auto_compact_token_limit = 900000
   disable_response_storage = true
   ```
   → 它们直接决定上下文管理维度（T03/T04/T12）的表现，留着就是"评测者给 Codex 加了外挂"
3. 删除 `model` 与 `model_catalog_json` 行？——**保留 `model` 用于记录**，但要在 baseline 表写清"模型 = deepseek-v4-flash（ccswitch 自定义 provider）"
4. 备份：`copy C:\Users\25634\.codex\config.toml runs\baseline\_backup\codex\config.toml.bak`，再改
5. 报告披露：`§1` 表格里 Codex 那行写明"自定义 provider（DeepSeek 后端）+ 默认参数"，并在 `§4.4 模型变量边界` 里说明

### 顺带的收益：给归因框架添一条 A 级证据路径

你现在的环境其实提供了一个**天然的同模型对照**机会：

| 产品 | 实际模型 |
|---|---|
| Codex | `deepseek-v4-flash`（经 ccswitch） |
| DSH | `MiniMax-M3`（默认路由），但凭据里**已有 `DEEPSEEK_API_KEY`** |

于是 `docs/01 §4.3` 的 DSH 专项对照可以这样设计：**把 DSH 也切到 `deepseek-v4-flash`**，那么

> **Codex(DeepSeek) vs DSH(DeepSeek) 的差异 = 纯粹的 Harness 差异**

这条比原来的"DSH 换件"更有力：它把主实验里唯一一个"模型不同"的干扰项直接消掉，属于 `§4.2` 的 **A 级实测对照**。反过来也能做（若 ccswitch 的 model catalog 里有 MiniMax，把 Codex 切到 MiniMax-M3 与 DSH 同模型）。

**但注意两条纪律**：
- 这个对照**不能混进主表**——主表仍是"五款各自默认形态"（`§4.3` 要求换件结论单独成节）
- 主实验跑测期间**不要动** ccswitch 档位；同模型对照安排到 W9（`docs/01 §8` 排期里的"DSH 换件对照"窗口）
