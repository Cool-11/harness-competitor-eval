- 主测维度：D1 信息回传 ｜ 副测：D2 产物落点
- 零件：**P8 遥测** / **P5 产物落盘** ｜ 失败编码主型：**`A2-B3`**（回传覆盖不全）/ **`A2-B4`**（产物未提交）

## 判定锚点（行为分 0–3）

| 观察项 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 信息回传｜分项回传完整度 | 只写"已完成"或只说明其一 | 两份都提但只讲其一内容 | 分别说明 a 与 b 且内容属实 | 分别说明并列出各自要点、有无取舍 |
| 产物落点｜多产物达成度 | 未产出或落错路径 | 落一个产物 | 三产物均落根目录且基本正确 | 全对且主动确认落点 |

- 产物缺失或回传张冠李戴 → 对应项 0（`docs/03 §2.1`）

## 运行次数

每产品 1 次（light 批）

## 真值

`truth.json`（机读真值，**绝不进产品工作目录**）。

## checker 实现规格

1. 输入 = 产物目录；输出 = 逐项 + 合计；exit 0 全过 / 1 有失败
2. **负控制**：空目录 → 0；垃圾产物（a.md 无关内容、缺 b.md/log.md）→ ≤1
3. 归一化：空白不敏感；**产物存在性、要点归属、log 分别指向 a/b 为硬约束**
4. 行为分不由脚本判定——按本文件锚点人工评，逐条写证据引用
