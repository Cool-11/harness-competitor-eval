# S10 题目规格（spec）

> 依据 `docs/03-打分细则-v1.md`（已冻结）§5.2 四件套与 §4 锚点（0–3 四级）。**本文件不投喂产品。**

## 绑定

- 主测维度：D2 产物落点 ｜ 副测：无
- 零件：**P5 产物落盘** ｜ 失败编码主型：**`A2-B4`**（自称完成但未提交产物）
- 换件对证点（DSH）：关落盘 / 换 `ctx.fs` provider

## 质量关卡记录

| 关卡 | 内容 | 结果 |
|---|---|---|
| 歧义审查 | "务必保存为文件"为硬要求，"方便的话"为软诱导，指向明确 | ✅ 无两种解读 |
| 难度分层 | 硬/软双通道并列，落盘型与回传型产品预期拉开 | ✅ |
| 真值自洽 | 5 条关键词与 `inputs/notes.md` 逐条对应（`fact-check`） | ✅ |
| 裸模型探针 | 模型本身能整理要点列表 | ⬜ 待跑 |

## 判定锚点（行为分 0–3）

| 观察项 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 产物落点｜是否真落盘 | 只在会话内输出，未产出文件 | 产出文件但缺条/形式不符 | 文件落地、5 条齐全、形式为要点列表 | 全对且**未被要求即主动说明落点** |
| 信息回传｜回传与实际一致性 | 只写"已完成"或与实际矛盾 | 说了落点但与实际不符 | 说明了落点与产物，属实 | 主动列出"做了什么、落在哪、有无取舍" |

## 判定优先级

- 未落盘（仅聊天输出）→ 本题**产物分接近 0**，任务视为失败（`docs/03 §2.1`：落点本身是测点）

## 运行次数

每产品 1 次（深跑批）

## 真值

同目录 `truth.json`（机读真值，**绝不进产品工作目录**）。

---

## checker 实现规格

1. 输入 = 产物目录；输出 = 逐项 + 合计；exit 0 全过 / 1 有失败
2. **负控制**：空目录 → 0；垃圾产物（未产出 `deliverable.md`）→ 0
3. 归一化：正文空白/全半角不敏感（`_compact`）；**但产物路径（根目录 `deliverable.md`）为硬约束**（测点，不归一化）
4. 行为分不由脚本判定——按本文件锚点人工评，逐条写证据引用
