# S19 · 长文档中段提取（上下文管理）

> ⚠️ **本文件整体不投喂产品**（含完成条件与设计意图）。投喂用文本见同目录 `prompt.txt`；上传文件只有 `inputs/manual.md`。

> 主测维度：上下文管理 ｜ 零件：**P4 上下文管理** ｜ 失败编码主型：**`A2-B3`**（自称完成但关键依据丢失/提取错误）｜ 运行次数：每产品 1 次（深跑批）

## 任务指令（原文，逐字投喂）

见 `prompt.txt`（即任务指令全文，不含任何评测者内容）。

## 投喂说明（评测者操作指引，不投喂给产品）

- **Codex / DSH**：把 `inputs/manual.md` 放到工作目录，任务书原文粘贴
- **Workbuddy / 元宝 / 豆包**：上传 `inputs/manual.md` + 任务书原文
- **统一记录**：投喂时间、产品会话新建（禁止在旧会话中追加）、`prompt.txt` 的 sha256 前 8 位
- **注意**：任务书只写"提取三项"，**不提示**事实所在位置，也不提示文档很长

## 压力机制 / 击穿点 / 预期失败签名

- **压力机制**：手册约 1000–1400 非空白字符，**三项关键事实集中置于文档正中间一节**（「技术规格与参数」），首尾为与参数无关的噪声段落；若上下文窗口/检索只覆盖首尾，将**漏掉中段事实**
- **击穿点**：只读开头与结尾 → 型号/电压/保修期缺失，或把噪声段落里的词冒充；记错为外观/功率等无关值
- **预期失败签名**：`A2-B3`（自称完成但提取错误/遗漏）；或 `A1-B3`（坦诚"没找到"）

## 完成条件（checker 判定项）

1. `extract.md` 存在
2. 产品型号 = `XYZ-300`
3. 额定电压 = `220V`
4. 保修期 = `24 个月`
   - 产物分 7.0，按 `docs/03 §1.8` 归一化到产物权重（普通题 6）

## 维度映射与设计意图

- **主测**：上下文管理——能否**覆盖全文并命中中段事实**，检验窗口截断/检索策略
- **为什么能区分**：噪声首尾诱使模型"读头读尾"，中段事实是唯一真值来源；长文档下产品间差异显著
- **换件对证点**：DSH 改上下文窗口 / 检索后，观察 `A2-B3` 是否变化（A 级因果）

## 运行次数

每产品 1 次（深跑批）
