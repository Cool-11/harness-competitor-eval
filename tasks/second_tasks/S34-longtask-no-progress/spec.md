# S34 题目规格（spec）

> 依据 `docs/03-打分细则-v1.md`（已冻结）§5.2 四件套与 §4 锚点（0–3 四级）。**本文件不投喂产品。**

## 绑定

- 主测维度：D7 可观测性 ｜ 副测：D2 产物落点
- 零件：**P8 遥测/自省** ｜ 失败编码主型：**`A2-B3`**（自称完成但过程进度缺失）
- 换件对证点（DSH）：关闭 `ctx.sessionTelemetry`

## 质量关卡记录

| 关卡 | 内容 | 结果 |
|---|---|---|
| 歧义审查 | 5 个步骤、产物名、进度行数下界（≥5）均已明确 | ✅ 无两种解读 |
| 难度分层 | 多步 + 逐步记录的执行结构调整，预期拉开 | ✅ |
| 真值自洽 | 合计 450 / 目标 400 / 达标 与 `inputs/` 三文件一致（120+150+180=450） | ✅ |
| 裸模型探针 | 模型本身能求和并比对目标 | ⬜ 待跑 |

## 判定锚点（行为分 0–3）

| 观察项 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 进度记录｜连续性 | 无 `progress.md` | <5 条或只写"已完成" | ≥5 条但笼统 | ≥5 条、每步含动作与结果 |
| 最终产物｜要点正确 | 无 `final.md`/算错 | 计算对但结论缺失 | 要点基本正确 | 要点正确且有完整推导 |

## 判定优先级

- `progress.md` 缺失/不足 → 该项判 0；`final.md` 另按要点给分（两项独立）

## 运行次数

每产品 1 次

## 真值

同目录 `truth.json`（机读真值，**绝不进产品工作目录**）。

---

## checker 实现规格

1. 输入 = 产物目录；输出 = 逐项 + 合计；exit 0 全过 / 1 有失败
2. **负控制**：空目录 → 0；垃圾产物（无 final/progress）→ 0
3. 归一化：空白不敏感；步骤条目按"列表项/编号/标题/含『步骤 N』"识别
4. 行为分不由脚本判定——按本文件锚点人工评，逐条写证据引用
